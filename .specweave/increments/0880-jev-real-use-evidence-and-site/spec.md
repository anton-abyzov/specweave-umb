# 0880 — Jev real use and evidence-led website

## Problem
Jev promotion has benchmark cards but no demonstrated production productivity gain. Existing benchmark uses synthetic EasyChamp inputs. SpecWeave homepage lacks an accessible path from Jev use cases to inspectable evidence and setup.

## Scope
In: audit practical Jev behavior, integrate a bounded safe EasyChamp workflow, measure actual calls against existing baseline, improve SpecWeave site mobile readability, premium Kie graphics, screenshots, deploy, release and local installation. Out: fabricated customer outcomes, automatic production writes based on model scores, social posting, unrelated dirty files.

## Acceptance Criteria
- [x] AC-01: Reproducible EasyChamp evaluation records source revision, real execution, baseline, accuracy, latency, cost, fallback and limits; no synthetic corpus described as production usage.
- [x] AC-02: EasyChamp has a tested bounded Jev use path with deterministic authorization and failure fallback; deployment state is explicit.
- [x] AC-03: SpecWeave website links practical use cases and evidence, distinguishes forecast from observed productivity, and works at mobile/tablet/desktop widths.
- [x] AC-04: Premium Kie graphics have model/settings receipts and visual inspection; screenshots show actual UI independently of generated art.
- [ ] AC-05: Relevant tests/build/lint and headless checks pass; deployed URLs and release/package installation have fresh receipts.
- [x] AC-06: Risk and acquisition report identifies implementation issues, limits, and concrete activation measurement; manual UI acceptance remains visible before increment closure.

## Approach
Three disjoint lanes: EasyChamp integration/evaluation; SpecWeave website and accessibility; Kie graphics and Jev implementation audit. One worktree each. Baseline current code, preserve unrelated changes. Prefer opt-in read-only semantic routing; never model-controlled authorization. Publish raw sanitized measurements alongside readable explanation. Keep all quantitative claims in HTML text, not generated artwork. Integrate lanes, run fresh checks, deploy via existing pipelines, release package if changed, install latest and read back version. Existing authorization covers implementation/deploy/release; manual UI acceptance required only for closure.
