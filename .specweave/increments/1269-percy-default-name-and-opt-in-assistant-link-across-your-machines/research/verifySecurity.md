1. **Reusing `ProjectLink` would send chat text and coordinator state to the other machine.** `ProjectLink.preview` (`apps/server/src/project/ProjectLink.ts:497-530`) returns more than goal, instructions and notes. It also returns `workspaceRoot`, a folder `fingerprint`, the coordinator `replica`, and `ranWhileDisconnected`, which is the first 400 characters of each user message (`turnsSince`, lines 470-490). The pairing in `LinkedPeerSync.pairsOf`/`describeCopy` also carries `coordinatorBinding`, plan digests and plan export, and the link supports takeover. Opening these paths for `kind:"personal"` would leak chat snippets and local paths, and would let one machine take over another's assistant. **Fix:** don't touch `refusePersonal` or the existing `isPersonalAssistantProject` guards (20 files). Build a separate, narrow personal-link route with its own export schema (title, icon, an allowlist of memory files, instructions). No coordinator binding, plan, replica, turns, workspaceRoot or takeover.

2. **The consent model copies a tool that has no human consent in it.** `studio_project_link_accept` (`mcp/toolkits/project/handlers.ts:1071-1080`) is an MCP tool. Another machine calls it under an all-projects work grant, and it is exposed remotely through `fleet/RemoteStudioMcpClient.ts:50,76`. So "approve like `studio_project_link_accept`" means "a grant is enough", which contradicts "A work grant is never enough." **Fix:** approval must be a UI action by a person on the target machine (web, desktop or iOS management session). It must not be agent-callable, must not be in `RemoteStudioMcpClient`'s tool list, and must be refused when the request comes from any agent thread. Show the requesting machine's label and key fingerprint on both ends.

3. **Nothing checks that both machines belong to the same person.** The fleet already contains machines shared through worker grants (for example the M1/Ministorm worker grants). "Use Percy from <machine>" would show and offer to link any connected machine's assistant, including its name, to whoever is setting up the new machine. **Fix:** offer linking only between machines enrolled under the same owner or management credential, not by fleet membership. Hide other owners' assistants from the setup prompt and the sidebar.

4. **`linkedCopyFor` lets a caller with no grant through.** The check `caller.grant !== null && !projectInGrant(...)` (`LinkedPeerRoute.ts:139-143`) skips the grant check entirely when `grant === null`. If personal projects become linkable here, a management-credentialed caller from any member machine passes without the new `personal-link:<projectId>` scope. **Fix:** require the explicit scope for every personal-link call, whether the grant is null or not, and check it before membership.

5. **The memory filter trusts file names and does not scan content.** A `user_*.md` name prefix is chosen by the model, and a memory file can hold an API key, a password or health data. Claude Code blocks synced writes with secret scanning (`content_secret`), and Codex redacts secrets from generated memory. **Fix:** check the allowlist at export time and also run a secret and PII scan on content before export. Block the file and surface it as `localOnly` instead of sending it.

6. **The `localOnly` tombstone leaks the file name, and merge can overwrite a local-only row.** `memoryExport` sends tombstones with the first page. A tombstone for "user_divorce.md" tells the peer that name exists. Separately, an incoming peer file with the same name could overwrite a `localOnly` row. **Fix:** send a tombstone only for files the linked history shows were already exported. Make merge skip or rename incoming files whose name collides with a `localOnly` row, and add a test for that collision.

7. **Re-wrapping secrets in the keystore can lose them, and lose pairing.** `getOrCreateRandom` is used for the session signing key (`SessionStore.ts:621`), the MCP OAuth signing key (`McpOAuth.ts:290`), asset and attachment signing (`AssetAccess.ts:839,873`, `AttachmentUpload.ts:70`) and the secret-request salt (`SecretRequests.ts:95`). If unwrap fails after re-wrap, these are silently regenerated. Unwrap can fail after a Keychain reset, a backup restore to new hardware, a DPAPI user change, or a headless launchd/systemd service without a libsecret session. Every paired client and signed URL would then break, and stored connection tokens would be lost. **Fix:** write the wrapped copy next to the old one and verify it by reading it back before deleting the `.bin`. On unwrap failure, fail closed and never regenerate. Keep an explicit recovery or export path. Test it on a headless Linux worker before turning it on by default.

8. **AC-08 can break legitimate external MCP clients.** The `context.caller &&` skip at `projectMemory/handlers.ts:19` exists because external clients have no thread. **Fix:** copy the rule `projectKnowledge/handlers.ts:17` already uses, and decide explicitly which credential types count as "management". Otherwise AC-08 either breaks Claude Code connected through MCP or is too loose.

9. **Unlink and "Forget from <machine>" don't let the user take data back from a peer.** Unlink leaves the peer's copy in place, and "forget" only deletes locally. A lost or compromised linked machine keeps everything. **Fix:** say so plainly in the link dialog. Add "Ask <machine> to delete what it received", applied the next time that machine connects. Also define what "last origin" means when a row came from a peer and was later edited locally: keep the row.

10. **The rename migration has two edge cases.** (a) The `percyRename` marker in server state can disagree with the event log after a restore. Write it in the same transaction as the `project.update`, or derive it from the event log. (b) Mapping a literal `"Aide"` on create to "Percy" also overrides a new user who deliberately types "Aide". Apply the mapping only when the client version is below the fixed build, and give it an end date.

11. **Empty-base merge doubles memory without asking.** When two existing assistants are linked, every file that differs becomes two contradictory files, and both load into every prompt. **Fix:** show a review step listing the conflicts before the first sync, or keep the peer's version as a non-loaded draft until the user resolves it.

12. **There is no audit trail for linking.** **Fix:** log link requests, approvals, scope grants, exports (file names only) and unlinks on both machines, and show the log in the assistant's settings.

13. **Parts of the design can be cut.**
    - The disk-encryption warning (T-09/AC-10). Detecting it reliably on Windows needs admin rights for `manage-bde`, and on Linux LUKS detection is unreliable.
    - The per-category toggles. Use one "memory and instructions" switch instead of three.
    - Three entry points for linking. Keep setup plus settings and drop the one-time card.
    - The `personal-link` grant scope plumbing in `workGrantsSnapshot`, if the dedicated route from item 1 checks owner identity and link membership itself.
    - Keystore wrapping on three operating systems at once. Do macOS first.

    Phase 2's read guard (AC-07) and the memory caller fix (AC-08) are worth shipping on their own.
