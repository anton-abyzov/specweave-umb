# Decision: automatic local checkpoints, explicit handoff

The installed 3.0.3 Stop hook deliberately forced a model continuation at 90%, ordered a handoff and stop, and marked it before success. Current Codex session readings show 100% weekly plan usage with available credits and no actual limit denial; treating a plan percentage as an execution stop is incorrect. Explicit handoff can release claims, update a shared pointer and wait on two Git network pushes. Those effects are inappropriate for parallel automatic saving.

Increasing the threshold leaves the false-stop and network-wait problems. A permanent daemon adds lifecycle and recovery state. Disabling automatic saving entirely loses useful recovery context. The selected implementation queues a bounded local worker at turn end, no more than once per five minutes per canonical worktree/session. StopFailure also queues it when the host reports a rate limit. Hooks always return empty JSON; they do not read quota transcripts or request model work. No Git network calls, claim changes or shared handoff pointer updates occur.

Each worker publishes a complete generation and atomically replaces current.json last. Failed Git or secret-scrub writes preserve the preceding successful save and allow retry. Four worker slots limit parallel resource use. A supervisor enforces an eight-second deadline and reaps its own POSIX process group, including Git helper descendants. Recovery instructions require checking current files and owners before restoring reviewed missing changes. Explicit handoff remains the cross-machine transfer mechanism; pickup does not apply automatic snapshots.

Limits: snapshots refresh after hook events, not continuously inside a long running turn. They remain local and contain the scrubbed handoff document and Git diff, not a remote backup. Windows cleanup is implemented but was not tested on a Windows machine in this session. Existing enabled settings adopt this behavior through the unchanged usage-guard command; --at remains accepted for compatibility. No Tailscale/proxy configuration was changed.
