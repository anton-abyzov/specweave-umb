# Board panel: collapsible state groups, machine legend and filter, denser cards

## Problem

Anton, November 18, 2026, on the Board panel of a project with 15 active increments, 8 of them blocked: "Rethink this. It could be improved. I believe we could have some kind of collapse panels for those types (active or blocked) and maybe some other optimizations. The color represents the machine, right? Same concept".

What the panel does today (app `a23f3593f`):

- **No way to fold anything.** The narrow panel is one long list: Active, In review, Planned, Done. Blocked work is spread through it and found only with the "Blocked only · N cards" switch or the "N blocked" button beside a heading (`apps/web/src/components/studio/shell/BoardPane.tsx:393-413`, `:454-464`).
- **The colored edge is unexplained.** It is the machine color of the card's lead thread that can still be opened, shown only when there is such a thread and the project's threads run on more than one machine or that thread moved (`BoardCard.tsx:62-66`, `board.css` `.sws-board-card[data-machine-color]`). It uses the same `data-machine-color` token as the sidebar square (`MachineDot.tsx`) and the machine chip (`MachineChip.tsx`), so the colors already agree. Nothing on the board says so, a card with threads on two machines shows one color, and the board cannot be narrowed to a machine.
- **Cards are tall.** Number and age take a row, the title a second, the meter a third, each thread a fourth, and chips a fifth. Up to five pull request chips wrap onto a second chip row.
- **A card often has no action.** Start, Continue, Resume and Review and close appear only when the card has no thread at all (`BoardCard.tsx:61`). A card whose only thread is resolved offers nothing, while its increment view offers Continue, or a request to plan it when it has no spec or no tasks (`boardIncrementModel.ts:200-228`).
- **Blocked reasons run together.** Example from Anton's screenshot: "New offline37profileattestation valid;113/148 exactartifactcopies recovered,35unresolved". The note is stored that way in the task ledger by the agent that blocked the task. The server already collapses runs of whitespace in ledger notes and cuts them at 200 characters (`apps/server/src/mods/SpecweaveProgress.ts:170-175`, applied at `:410`); it removes no space that was written. The SpecWeave CLI sets no note limit that would explain the squeezing.

## Scope

In: the Board tab's list of cards in `repositories/anton-abyzov/specwithcode/apps/web`. Five foldable groups with Blocked first, a machine legend that is also a filter, a denser card with one action and one pull request chip, and a display-only repair of punctuation spacing in notes. Client only.

Out: the contracts and the server (`projects.board` is unchanged); the increment view's layout (it gains the note repair, the pull request state rule of AC-12 and the out-of-reach sentence of AC-11, nothing else); the "Start a board for this project" state and the zero-increments sentence (`BoardPane.tsx:126-146`, `:421` at `a23f3593f`), which increment 1387 is redesigning; drag to change state; any change to how agents write block notes (D-08).

## Acceptance Criteria

- [ ] AC-01: **Groups.** The board has five groups: Blocked, Active, In review, Planned, Done. Groups, counts and labels are all worked out from the board after thread promotions (the output of `boardWithPromotions`, which moves a planned card a thread works on into Active and adjusts the server's counts with it). Blocked is derived on the client: every card for which `boardCardBlocked` is true (paused, or a blocked task; never a Done card; a card that is both counts once) is listed in Blocked and not in its state group, and carries a label with the state it has on that promoted board ("Active", "In review", "Planned"). The Blocked heading counts those cards. Each state heading counts the promoted board's count for that column minus its blocked cards, so the five counts add up to the server's total. With no blocked card the Blocked group is not rendered; the four state groups always are, with a count of 0 when empty, also under a search or a machine choice.
- [ ] AC-02: **Folding.** Each group is a `section` labelled by its heading (`aria-labelledby`). The heading is an `h3` holding one button with a chevron, the name and the count; `aria-expanded` says its state and, while open, `aria-controls` names the body. Pressing it hides the group's cards and its "Show more" or "Show older" button and keeps focus on the button. Folded groups are remembered in local storage per machine connection and project (`environmentId:projectId`) and are restored after a reload. Every group is open until the person folds it. Folding never discards cards already loaded: unfolding Done shows the same cards as before.
- [ ] AC-03: **Search.** While a search is typed, every group is shown open and its button is `aria-disabled` (a press changes and stores nothing), the rule the Threads list uses (`ThreadsPane.tsx:934-952`). Clearing the search restores the remembered folds.
- [ ] AC-04: **Removed.** The "Blocked only" switch, its note line, its turning itself off, and the "N blocked" button beside a heading are gone. `boardFilterLabel` and the filter state are deleted, not left unused.
- [ ] AC-05: **Layouts.** The pane measures its board and names the layout (`data-layout`), replacing the CSS container query, so the groups are rendered in the document in the order they are shown and Tab follows the screen in both layouts. Stacked (a board under 720 px wide, or any width with the increment view open beside it): Blocked, Active, In review, Planned, Done. Side by side (720 px and wider, view closed): Blocked is a band across the top with its cards in columns of at least 240 px, then Planned, Active, In review and Done as columns, today's column order. A folded column becomes a rail 36 px wide; the rail is the same heading button at the full height of the column, with the name and count written vertically; the other columns share the freed width. A folded Blocked band is its heading alone. Nothing scrolls sideways at 360 px.
- [ ] AC-06: **Keyboard and the increment view.** Up and Down move between the cards on screen in document order and never land in a folded group: stacked that is the order of AC-01; side by side it is the band row by row, then Planned, Active, In review, Done, each top to bottom. With the view open the board is stacked, so the arrow keys and the view's previous and next step through the stacked order. Closing the view returns focus to its card, or to the heading button of the group the card was last in when the card is not on screen, or to the first heading button when that group is gone. When a refresh moves or removes the card that has focus, focus follows the card to its new place, or goes to the heading button of the group it left; it is never taken from an element outside the list. Opening an increment by a link or by going back, when its group is folded, unfolds that group at once and remembers it; it never waits on the threads, so a machine that is off cannot keep the card hidden. If the threads then move that card from Planned to Active, the fold of Planned is given back as it was and Active is unfolded instead. That is the only move followed: any other change of group unfolds nothing and gives nothing back, and once the person folds or unfolds by hand the card's group, or the group a promotion would move it to (Active or Blocked), those are theirs. A card that changes group later, while its view is open, unfolds nothing, and the person can fold the open card's group.
- [ ] AC-07: **The edge means the machine.** A card outside Done shows on its leading edge the color of every machine one of its threads runs on: one segment per execution machine (the machine that runs the thread, not the one that serves it; two threads on one machine give one segment), resolved threads left out, in the card's thread order, at most three segments. It appears under the condition the machine name on a thread line appears: the project's threads run on more than one machine, or a thread of the card moved. A thread on a machine that cannot be reached still counts; its line says "Host offline". The colors come from `data-machine-color`, the token the sidebar square and the machine chip use. Color is never the only sign: the edge has a text label naming its machines ("Runs on Desk, Laptop and Spare"; past three, "and N more machines"), and the legend names every color. Finished work carries no edge.
- [ ] AC-08: **Legend.** Whenever a card can show an edge (the condition of AC-07), a "Runs on" row under the search lists each machine that has an open card (any card outside Done): its color square (`MachineDot`), its name and its count of open cards, with a tooltip that says open cards with a thread on that machine carry the color on their edge. A single entry is only a legend, with nothing to press, unless it is the choice, which can always be let go; a machine and "No thread" are two entries and narrow the board. The edge's label ("Runs on Desk and Laptop") is read by screen readers and shown on hover; it is not a keyboard stop, and keyboard users read the same from this row, whose names and counts are plain text. When no card can show an edge the row is not rendered.
- [ ] AC-09: **Machine filter.** With two or more entries the legend entries are toggle buttons (`aria-pressed`), one at a time, with "All" first. The edge, the legend and the filter speak of open work only. A chosen machine narrows Blocked, Active, In review and Planned to the cards the edge rule of AC-07 puts on that machine, and each of those headings then counts the cards it shows. Done is not narrowed: under a choice it shows no cards and no "Show older", its heading keeps the whole count, and a line says "Finished work is not sorted by machine. Choose All to see it." "No thread" is offered for open cards with no unresolved thread; its tooltip says so. Until every thread has said which increment it works on, the entries show no counts, "No thread" is not offered, no entry can be chosen (a choice already made can still be let go) and a status line says "Reading threads…"; when a thread that is not resolved is left unread because one machine has more threads in the project than the board reads (800; resolved threads beyond that do not count, so a long-lived project still narrows), the line says the board cannot be narrowed by machine. Resolved threads left unread that way have no line on their card and are not counted in the view's finished list, and nothing says so; that was already the case for every thread past the limit and is not changed here. The choice is not remembered between visits. "All" is there whenever a choice is held, also when no machine has an entry for the moment, so a choice can always be let go. The choice holds while its entry exists, also when it is the only entry left (a search that matches only that machine's cards) and while the threads are read again. Once the threads have answered it lets go by itself when its entry is gone: its machine has no open card on the board, which includes a search that leaves that machine no match (an empty board would read as "not found").
- [ ] AC-10: **Denser card.** The card has at most four parts. (1) The open control: one button (`data-board-card`, `aria-expanded`, `aria-controls` while open) holding the number and title on the first line (title up to two lines), with the state label of AC-01 and the age at the right. It opens the increment view, as today. Parts 2 to 4 are its siblings, never nested in it. (2) One status row: the meter, the task count ("6/15"), the pull request chip and the action. The task count is the open button's description (`aria-describedby`, read as "6/15 tasks done"). The meter's track is 56 px on every card, so two bars can be compared. A card with no tasks shows no meter and no count, and neither does a Done card (D-11). (3) On a blocked card, one box: a first line that says what is stuck ("2 tasks blocked", "Paused + 1 task blocked", with "rest can continue" when it applies; left out when the card is only paused and gives its reason), then up to two reasons. (4) At most two thread lines, unresolved first, then "N more threads", which expands in place. In the board fixture at a 390 px panel, the card with one thread, tasks and one pull request is at most 93 px tall (124 px at `a23f3593f`, a quarter less); `verify.mjs` asserts it.
- [ ] AC-11: **One action.** Every card outside Done shows at most one action button besides its open button, its thread lines and its pull request chip, always at the end of its status row, also where the row wraps, chosen by the rule the increment view uses (`viewPrimaryAction`): "Open thread" when a thread on it can be opened (it opens the first such thread in the card's order); otherwise a request for the coordinator: Start, Continue, Resume, Review and close, Plan the tasks or Plan it with the coordinator, which put the same request in the coordinator's composer as today. A request appears only once the threads have answered and only when the person can send. A card whose threads are all resolved gets the request. A card with no thread that can be opened and a thread on a machine that cannot be reached also gets it, as its increment view does since 1338, but that thread may still hold the work; so every request that can set the coordinator to work on it (the card's, the view's primary one and the view's two blocker requests) ends by naming the thread and its machine and asking the coordinator to check before starting another worker beside it. That is text in a draft the person can edit: it asks, it guarantees nothing. Thread lines still open their own threads.
- [ ] AC-12: **Pull requests.** A card with one pull request shows one chip with its number, which opens it. A card with several shows one chip "N PRs" that opens a menu listing each number, with its state word (Open, Draft, Merged, Closed) only when a thread of the project has read that pull request from its host, and no word otherwise; "Open" is never assumed for a pull request a thread only linked. The same rule now feeds the increment view's pull request states. The menu works from the keyboard, Escape closes it and returns focus to the chip, and it never closes the increment view. No contract field is added.
- [ ] AC-13: **Punctuation spacing in reasons.** One function prepares a block or pause reason for display, on the card and in the increment view, and the task notes in the view's task list. Text inside backticks is left exactly as written. Outside backticks it collapses runs of whitespace (new only for pause reasons; the server already does it for ledger notes) and adds a space after a comma or semicolon that is directly followed by a letter or digit of any script, except: a comma between two digits ("1,234", "1,5x"); inside brackets, also when the list runs across spaces ("f(a,b)", "[T-01,T-02, T-03,T-04]"), but a bracket that never closes is not a list: it opens nothing, the repair goes on after it, and lists that do close in the same note stay as written; the semicolon that ends a character reference ("&amp;"); and anywhere in a run of text that is a link, a path or a file name (it contains "://" or a backslash, starts with "data:", "mailto:" or "file:", has a slash beside a letter, or ends in a dot and one to eight letters or digits of any case, as "a,b.txt" and "export,final.CSV" do). A slash between two numbers is a ratio, not a path, so "valid;113/148" is repaired. It never splits a word: "offline37profile", "T-64", "HTTPX" and "1.0.343" are unchanged, so squeezed words stay squeezed (D-08). Requests to the coordinator keep quoting the note as written. Reasons wrap inside long words and clamp at two lines on the card, as today. Unit tests use made-up strings only and cover each exception above.
- [ ] AC-14: **Proof.** `apps/web/tests/project-board/verify.mjs` passes against the new board in light and dark, with checks for: the group order and counts in both layouts; the band above the columns; the removed switch; a fold as a rail and as a row, surviving a reload; the search opening and locking folded groups; a link into a folded group; the arrow walk across columns and the stacked order beside the view; the legend's entries and its colors against the edge; the edge label; the machine filter and Done under it; "No thread"; the threads-not-answered state, with one machine still unread and nothing of it on the board; the cut thread list and its line; focus following a card that a refresh moves or removes, and staying put when it is elsewhere; the action ending its row on a band card; the action on a card with a live thread and with only a resolved thread, and the request beside an unreachable thread (card and view); the pull request menu, its state words, and Escape with and without the view open; the meter's track width; and the card height limit of AC-10. Unit tests cover the cut thread list, edge dedupe and cap, pull requests no thread has read, a board with one machine and no legend, focus when a card moves, a choice whose machine is the only entry left, the choice while threads are read again, one machine plus "No thread", and the link that unfolds at once and follows a card the threads move. Headless captures, light and dark, of the wide board, a folded column and band, a chosen machine, the pull request menu, the split view, 390 px open and folded, a link into a fold, the threads-reading state and the cut thread list are saved in this increment's `reports/screens/`. The design-token guard, the focused tests, the web typecheck and the web build pass.

## Approach

Design and mockup: `reports/board-groups-mockup.html`.

1. `apps/web/src/studio/projectBoardModel.ts` (pure, tested first): `BOARD_GROUPS`, `BOARD_GROUPS_WIDE` and `BoardGroupId`; `boardGroups(cards)` and `boardGroupCounts(counts, blocked)`; `boardStateLabel`; `boardCardMachines(threads)`, `boardEdgeLabel`, `boardCardOnMachine` and `boardMachineOptions` for the edge, the legend and the filter; `boardOutOfReachNote`; `boardNoteText(note)`; `boardPullRequestChip(urls)` and `boardPullRequestStates(threads)`. `boardBlockedCounts`, `boardFilterLabel`, `boardColumns` and `BOARD_STACK_ORDER` go.
2. `BoardPane.tsx`: groups replace columns in the render loop. A measured layout (`useBoardLayout`, one `ResizeObserver` for both the view's place and the side by side switch) names the layout and the render order. Fold state goes through `useLocalStorage` with a schema, keyed `environmentId:projectId` (new key `studio:project-board-folded:v1`). The walk, the arrow keys and both focus returns read groups. Paging: every group, Blocked included, shows 40 cards and "Show N more" by what it holds after the machine choice; Done pages older work from the server as today, by its server count; a search keeps the paging and starts each group at its first page. Group rendering is `BoardGroupSection.tsx` and the legend `BoardMachineLegend.tsx`, so the pane stays near its present size. The "Start a board" state and the zero-increments sentence are not edited.
3. `BoardCard.tsx` and `BoardThreads.tsx`: the dense anatomy, the state label, edge segments, `viewPrimaryAction` for the action, the pull request chip and menu (`components/ui/menu`), `boardNoteText` on reasons; the thread hook also reports `cut`. Both new card props are optional. `BoardIncrementView.tsx` gains `boardNoteText` on the blocker and pause reasons and the out-of-reach sentence of AC-11 on its request.
4. `board.css`: group headings, the band, rails, the dense card, the legend, `[data-layout]` in place of the container query. Tokens only. `board-view.css` is not edited: it has no column rules, only the view's column chip.
5. Tests: `projectBoardModel.test.ts`, `BoardPane.test.tsx`, `BoardPane.view.test.tsx`, the fixture `tests/project-board/mocks.tsx` and `verify.mjs`.

Rejected:

- **Keeping the switch and adding folds.** Two ways to find blocked work, and the heading would still read "Active 15, 8 blocked". Anton asked for Blocked as a type of its own.
- **A blocked card in both groups.** Counts stop adding up, and the card walk and focus return need a card to be in one place.
- **A fifth column for Blocked in the wide panel.** Five columns at 720 px are 130 px each. A band keeps the four columns in the order work moves.
- **CSS `order` for the two layouts.** Stacked and side by side put Planned in different places; reordering by CSS leaves Tab and the arrow keys on the other order.
- **Splitting squeezed words.** Any rule that splits "offline37profileattestation" also breaks "T-64", "HTTPX", version numbers and hashes. The board repairs punctuation spacing only and says so.
- **Narrowing Done by machine.** Resolved threads color nothing, so it would nearly always be empty, and only the newest 30 done cards are loaded, so any count would be partial.
- **Pull request states on every chip.** The card carries URLs only; states are known for pull requests a thread has read. Showing all states needs a contract field and a server read.
- **Remembering the machine filter.** A board that opens narrowed, with cards missing, reads as lost work. Folds are remembered because a folded heading still shows its count.

Risks:

- **1387** (the board's empty state and example board, still in spec review, no code yet) will render the real `BoardCard` from sample files and edit the fixture's `main.tsx` and `verify.mjs`. 1391 lands first. The card's new props (`stateLabel`, `pullRequestStates`) are optional, so sample cards written against today's card keep compiling. 1391 does not edit `main.tsx`; in `verify.mjs` it owns the board pages and leaves the `setup` page to 1387, apart from one renamed selector. The 1387 thread gets the merged commit to rebase on.
- **1338** (closed) named its traps: Blocked is derived after promotions; a paused card with every task done stays out of In review and is labelled Active; a Done card with a leftover blocked task stays in Done; the focus fallback needs a target that always exists.
- **Focus on refresh** restores only when focus fell to the page because the focused card left; it must never move focus that is anywhere else.

### Defaulted (change any before sw-do)
- D-01 Blocked is a group and the "Blocked only" switch goes. This reverses 1338 D-06 ("Blocked stays a state on the card and a filter") on Anton's November 18 request.
- D-02 Every group starts open; nothing is folded for the person.
- D-03 Folds are remembered per project and machine connection, not globally as the Threads list does, because boards differ in size from project to project.
- D-04 The machine filter is not remembered between visits.
- D-05 The edge shows every machine with an unresolved thread on the card (up to three), not only the lead thread's. A thread on an unreachable machine counts. A card with only such a thread still offers its request, as 1338's view does (its tests pin Continue beside an offline thread, and a card that could never be continued while a machine is off would be a dead end), and the request now names that thread so the coordinator checks before starting anyone (AC-11). Withholding the button was the other fix the review offered; it was not taken for that reason.
- D-06 Several pull requests open a menu on the card instead of opening the increment view.
- D-07 In the wide panel a folded column becomes a rail; folds mean the same in every layout.
- D-08 Note repair is punctuation spacing only, so the squeezed words of Anton's screenshot ("offline37profileattestation", "exactartifactcopies") stay squeezed; only "valid; 113/148" and "recovered, 35unresolved" gain their spaces. The real fix is at the writer and is not built here. Follow-up F-01, for the SpecWeave side and proposed to the coordinator in this thread's report (it is another repository's work): `specweave task block` warns on a note with squeezed words, and the sw-do skill tells agents to write block notes as plain sentences.
- D-09 The edge, the legend and the machine filter cover open work only; Done is never narrowed or colored.
- D-10 A search that leaves the chosen machine no match lets the choice go, and it does not come back when the search is cleared. A search that leaves only that machine keeps it.
- D-11 A Done card shows no meter and no task count. Finished work reads by number, title and age, and a full bar on every Done card is noise; the increment view still shows its tasks. Say so if you want the count back.

### Known limits, left by the last review as "can follow"
- L-01 (AC-13) When brackets of different kinds interleave inside one list and one of them never closes ("(a,b [c,d) e,f"), the repair picks the wrong bracket as the unclosed one and adds a space at the front of the list. Display only; the request to the coordinator quotes the note as written. Fix: in the pre-scan of `boardNoteText`, a closing bracket removes the newest opener of its own kind.
- L-02 (AC-06) A link to a card the board has not loaded yet: a fold of Active or Blocked made by hand before the card arrives is undone if the threads then promote the card. Fix: `toggleGroup` in `BoardPane.tsx` also settles the follow when the opened card is not in the data yet and the toggled group is Active or Blocked.
