## [high] `apps/server/src/project/CoordinatorMessageReceiver.ts:919–935` checks before the thread lock

The route and flush now apply the same machine-reach decision to the admitted fingerprint; a later group no longer inherits the first group's time. But one timestamp covers all rows in a group, and destination lookup, reference checks and the serialized dispatch follow. An otherwise idle coordinator can start after the sender's grant deadline if dispatch waited for the lock. The dispatch-time policy applies to the receiver's runtime and model, not to the admitting sender (`apps/server/src/orchestration-v2/Orchestrator.ts:4735–4753,13700–13703`). Recheck authority after taking the lock, before committing the start, using current time and only the rows authorized for that frame.

## [high] `apps/server/src/project/CoordinatorMessageReceiver.ts:861–889` checks the session but not its device approval

The HTTP path authenticates a device-bound credential against its approval. The session listing used by flush retains the session identity and scope but does not expose that binding. If approval cannot be verified while the session row remains live, the route refuses the credential but flush can still wake the coordinator. This finding is specific to device-bound credentials; it does not mean all session revocations are ignored. See `apps/server/src/handoff/handoffRoute.ts:325–331`, `apps/server/src/auth/EnvironmentAuth.ts:1599–1612`, `apps/server/src/auth/SessionStore.ts:1378–1392` and `apps/server/src/fleet/ConnectDeviceTrust.ts:835–847`. Revalidate the server-derived admission binding through the auth service and fail closed if it cannot be verified.

## [high, upgrade only] `apps/server/src/orchestration-v2/Orchestrator.ts:2354–2364` can drain pre-fix state

The base revision stored a `queuedRun` before trying to withdraw it (`apps/server/src/project/CoordinatorMessageReceiver.ts:974–989` at `5acf4ba9`). At head, `apps/server/src/project/CoordinatorMessageStore.ts:89–105` no longer tracks it, but that does not remove the independently persisted orchestration run. The ordinary consumer can start it without sender authorization. This matters only for a machine that ran the pre-fix code and retained such a run; there is no evidence here of a deployed instance. In that upgrade path, quarantine legacy receiver runs before queue consumption.

## Other requested checks

- **Start-only branch and wire boundary.** The receiver sets `mode: "queue"` and `startOnly: true` itself (`apps/server/src/project/CoordinatorMessageReceiver.ts:974–994`). A steerable active turn is not steered. Busy and usage-limit branches refuse before publishing a queued run; that refusal is not recorded as a successful dispatch (`apps/server/src/orchestration-v2/Orchestrator.ts:6467–6484,13555–13564`). A post-persistence projection error does not turn a start into a queued run. The coordinator-message wire cannot set the bit. It is not private to the server across all interfaces: the general orchestration RPC includes it (`packages/contracts/src/orchestrationV2.ts:3513–3514,4430–4433`). That limits what an already-authorized dispatch may do; it is not a new grant of access.
- **Exact membership.** The destination binds environment and project; multiple sender copies on one environment are refused. An absent local member can be stamped `"-"` and stored, but a destination without its exact local member cannot wake a coordinator. See `apps/server/src/project/CoordinatorMessageReceiver.ts:328–341,505–513,789–803`. No authority bypass was found from substituting a sibling copy's stamp.
- **Uncertain delivery.** An unchanged attempt reuses its command ID. The delivered update is guarded by each sent row's ID and revision, so neither a newer merge nor a new member of a digest is marked delivered by the earlier success. The round 3 queued-reconciliation defect is gone for new sends. A separate duplicate remains possible: if a digest starts but its acknowledgement or delivered-state write fails, a change to the group gives the retry a new command ID and it can repeat unchanged members. See `apps/server/src/project/CoordinatorMessageReceiver.ts:833–841,966–975,997–1019` and `apps/server/src/orchestration-v2/ThreadManagementService.ts:625–629`. Reconcile the original attempt and exact revisions before regrouping. This is delivery integrity, not a separate authority blocker.
