# Sleek popups: one popup standard across the desktop and iPhone apps

## Problem

Anton (November 18, 2026): "Make sure that all popups are really looking sleek and up to the best standards in UI."

Evidence: his screenshot of the "Runs on m4" machine menu in the EasyChamp project on M5 (`~/.specwithcode/m4/userdata/attachments/project-coordinator-1332065e-795b-4f98-91c4-f114917e53f6-8511c174-c133-4931-a967-459fb4fa1ade.png`).

- The menu stretches across the whole window, about 1,580 px wide, and covers the Threads panel.
- Two helper lines ("Viewing moves nothing..." and "Not linked: these are separate projects...") run edge to edge on one line each.
- Section labels ("View this project on", "This project", "On m4") are plain muted text with no rhythm; the two machine rows have no icon while the action rows do.

Root cause in code (`apps/web/src/components/ui/menu.tsx`, `MenuPopup`): menus size to their content with only `max-w-[calc(100vw-2rem)]` as a cap, so any long text sets the width. `PopoverPopup` has width tokens (`sm`/`md`/`lg`), menus do not. The app has about 94 `MenuPopup`, 56 `PopoverPopup`, 79 `DialogPopup`, 31 `AlertDialogPopup`, 126 `SelectPopup`, 7 `ComboboxPopup` and 5 `SheetPopup` call sites, plus one toast component with about 880 callers, and no written popup standard.

## Scope

In:

- An inventory of every menu, dropdown (select, combobox), popover, dialog, alert dialog, sheet and toast variant in the desktop app (web UI), and the iPhone app (`apps/ios`, SwiftUI) where it applies. Generated by a script, one row per call site, with a capture status on every row.
- Headless screenshots at narrow and wide window sizes, light and dark, before and after.
- One popup standard (below), applied in the shared primitives first, then at call sites, worst offenders first by measured width, starting with the machine menu.
- The machine menu's visual shell only (width, wrapping, header style, spacing, icons, placement).

Out:

- Tooltips: not in Anton's list; they already use one component. Listed as a count only.
- The machine menu's wording and items ("View this project on", "Send to another machine", "Link m1", "Move running threads"): owned by the thread "Rethink copies, sync and handing off work". Any move of its helper text behind an info affordance waits for that thread's yes (D-03).
- Android, the Expo app (`apps/mobile`), the Chrome extension and marketing site.
- Native iOS system sheets and alerts that already follow Apple's layout: inventoried and captured, not restyled.

## The popup standard

1. **Width.** Menus default to a 20 rem (320 px) maximum and a 12 rem minimum; tokens `sm` 16 rem, `md` 20 rem (default), `lg` 24 rem, `xl` 32 rem for pickers with long rows. Popovers keep `sm`/`md`/`lg` and get `xl`. Dialogs: `sm` 24 rem, `md` 32 rem (default today: `max-w-lg`), `lg` 40 rem, `xl` 48 rem. Every popup is also capped at `100vw - 2rem`. No popup is wider than 48 rem except full-screen viewers (file, image, report), which are listed as exempt.
2. **Padding.** Menus: 4 px frame, rows 8 px inline padding, 28 px row height on desktop, 40 px touch. Popovers: 16 px default, 12 px compact. Dialogs: 24 px.
3. **Section headers.** One style: 11-12 px, medium weight, muted, 8 px top gap above every header after the first, separators only between groups that are not already headed.
4. **Icons.** Rows in one group either all carry a 16 px leading icon or none do; status words sit trailing and muted.
5. **Helper text.** At most one short line (about 60 characters) under a header, wrapping inside the width cap, never setting the popup width. Longer explanations go behind an info affordance that is keyboard reachable.
6. **Keyboard focus.** Menus: arrow keys move through items, Escape closes and returns focus to the trigger, Home/End jump. Popovers and dialogs trap focus and restore it. A visible focus ring on every focusable element.
7. **Placement.** Every popup stays inside the window with an 8 px margin, flips side when it would overflow, and scrolls inside itself when taller than the window.
8. **Themes.** Light and dark, with WCAG AA contrast for text (axe clean on the captured states).

## Approach

Fix the primitives, then the call sites that override them.

1. `apps/web/src/components/ui/menu.tsx`: `MenuPopup` gets `width` (`sm`/`md`/`lg`/`xl`/`auto`, default `md` = `max-w-[min(20rem,calc(100vw-2rem))]`) and `collisionPadding` 8; `MenuGroupLabel` gets the header rhythm; new `MenuHint` (wrapping muted helper, `text-pretty`, max one short line by convention). `popover.tsx` gets `xl` and 8 px collision padding; `dialog.tsx` gets size tokens with the current `max-w-lg` as `md`.
2. `apps/web/src/components/studio/OrchestratorSwitcher.tsx`: width token, `MenuHint` for the two helper lines, leading machine icon on machine rows (the same machine glyph the chip uses), headers per the standard. No phrase changes.
3. Call sites found by `git grep` for `MenuPopup|PopoverPopup|DialogPopup` with `w-`, `min-w-`, `max-w-` classes: each moves to a token or is marked exempt in the inventory.
4. Fixture `apps/web/tests/popup-standard/` (vite + `verify.mjs`, the `coordinator-menu` pattern): renders the machine menu with the coordinator-menu mocks and a gallery of each primitive with long content, measures each popup's bounding box against the cap and the viewport, runs axe, checks keyboard, shoots light and dark at 390, 840 and 2000 px. It runs on origin/main first for the before shots.
5. Inventory script `apps/web/tests/popup-standard/inventory.mjs`: lists call sites into JSON; the report renders it with capture status.
6. Real-app capture: the built web app against a local dev server with a throwaway state directory, headless, clicking through the popups it can reach (sidebar, composer, project header, settings, thread menus).
7. iPhone: grep `apps/ios` for `.sheet`, `.alert`, `.confirmationDialog`, `.popover`, `Menu`, `contextMenu`; capture in the iOS Simulator.

Rejected: restyling each of the ~390 call sites by hand (drifts again); a global CSS override on `[role=menu]` (fights Base UI positioning and the menus that need `xl`).

Risks: the default cap can truncate a wide picker that relied on content width (model picker, project picker); the measurement step finds these and gives them `lg`/`xl`. The composer-foot fit logic measures triggers, not popups, so it is not affected, but its fixture is rerun.
