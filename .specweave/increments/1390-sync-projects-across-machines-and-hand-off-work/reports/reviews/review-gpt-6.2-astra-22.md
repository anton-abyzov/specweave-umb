## Follow-up (non-blocking)

1. **Medium: the staging root is shared by name, not by user.** `apps/server/src/fleet/ProjectSyncExtras.ts:615,622-633`. On a host where two accounts share `/tmp`, the first account creates the fixed root. The second account rejects it on UID for every extras send. The old code allocated a fresh temp directory per call. Also, for an existing same-owner root, `EEXIST` is accepted without verifying the README contents or existing directory mode. Use a per-user staging location and validate the existing root before reuse. This is a safe refusal on the second account, not a reason to weaken the owner check.
2. **Medium: clearing an environment-only object pool can refuse a previously valid send.** `apps/server/src/fleet/ProjectSyncExtras.ts:641-649,665-668,700-703`. If a source tip depends on objects available only through `GIT_ALTERNATE_OBJECT_DIRECTORIES`, private commands no longer inherit that pool, and the alternates file names only the source's primary store. In disposable stores, the source and the old private environment could read a pool-only blob; the new private environment could not. Preserve private write isolation and materialize the required source objects, or detect this setup and return a specific refusal.
3. **Low: an already-existing, unreachable source blob can still be pruned.** `apps/server/src/handoff/checkpointGit.ts:258-265`; `apps/server/src/fleet/ProjectSyncExtras.ts:524-525,559-568,700-703`. This is a limit of the prune fix, not a regression in the fresh-object case. A file can match a previously staged and then unstaged blob. With a private index and object directory, real `git add` reused the source blob without writing a private copy. It was readable privately before `git prune --expire=now` and absent afterwards, without any branch rewrite. The working file stays intact. If sends must survive this case, materialize borrowed objects the bundle needs before waiting for the peer and add that fixture.
4. **Low: a failed setup can leave a folder without the cleanup notice.** `apps/server/src/fleet/ProjectSyncExtras.ts:438-440,595-600,678-695,707-710`. If marker creation fails after `mkdtemp`, the disposer correctly refuses to remove the unmarked directory. The initialization catch discards that outcome, and `own` has not been assigned, so the caller reports only the setup error. Propagate the leftover path and cleanup status along with the original error. Do not remove an unverified folder.
