## P2-38 [high] A live listing substitutes for a missing fetch

`apps/server/src/fleet/ProjectSync.ts:614-619`, `:637-667`. After a restart, a tracking ref already populated by a person's Git client can be ahead of the checkout. With no record, facts do not flag a mismatch. When the live listing agrees, `run` advances the checkout without a successful Sync fetch. The second online attempt after a record was dropped has the same problem. A listing proves what origin advertises, not who fetched it. Require a matching successful Sync fetch on both the online and offline paths; when the record is missing, fetch again or decline.

## P2-39 [high] An origin rewrite does not invalidate offline permission

`apps/server/src/fleet/ProjectSync.ts:425-426`, `:637-638`, `:665-667`; `apps/server/src/fleet/projectSyncOrigin.ts:182-186`. The record compares the literal `remote.origin.url`, not the effective fetch URL. If an `insteadOf` rule now points the same configured URL at a different, unreachable repository, `run` accepts the old repository's record. Keep the configured address for display, but bind permission to Git's expanded fetch URL and check it again before the write. A `pushurl` is not the fetch URL.

## P2-40 [high] A second window can replace the first window's approved tip

`apps/server/src/fleet/projectSyncOrigin.ts:164`; `packages/contracts/src/projectSync.ts:355-363`. Window A fetches tip B and leaves its dialog open. Window C fetches newer tip D for the same project and checkout. A's request carries only the path and the other machine's branch. It reads C's record, sees D locally and on origin, and moves to D. Both fetches can finish before A presses Sync: no overlapping commands are needed. Separate project IDs are isolated; two windows on one project are not. Return a fetch generation with the facts and require it, or an equivalent expected ref and object ID, on the move. For older requests without it, do not silently substitute the latest plan.

## P2-41 [high] The upstream's local destination is mistaken for its source branch

`apps/server/src/fleet/ProjectSync.ts:139-149`, `:561-570`. Git permits a fetch rule that stores remote `release` as local `refs/remotes/origin/stable`. This configuration is admitted. Sync's own fetch intentionally stores **remote `stable`** there, then the upstream check reconstructs `refs/heads/stable` from the destination suffix. If both branches exist, it verifies the wrong branch and can move a checkout configured to follow `release` onto `stable`'s commits. A second remote mapped into the same local tracking namespace has the analogous problem. Read the upstream remote name and remote source ref from Git (`upstream:remotename` and `upstream:remoteref`); resolve the source in Sync's explicit mapping, or refuse a mapping it cannot reconcile. Keep display names out of the proof.

## P2-42 [high] A pre-fetch advertisement remains usable after the fetch contradicts it

`apps/server/src/fleet/ProjectSync.ts:460-483`, `:516-528`. Origin lists B, then changes to C before the fetch. The fetch writes C. Facts correctly return `upstreamMoved`, but the record still authorizes B. If a later local fetch restores the tracking ref to B before any `run`, an offline run permits B, even though this Sync fetched C. B can already exist locally from an earlier fetch. The test at `apps/server/src/fleet/ProjectSync.origin.test.ts:174-190` stops at the refusal in the plan; it never consumes the record afterwards. Build permission from this fetch's actual ref/OID results, publish it only on success, and never retain permission for a mismatching ref. Keep inventory's advertisement separate from the permission to move.

## P2-43 [high] Final validation and the merge do not share a checkout write guard

`apps/server/src/fleet/ProjectSync.ts:672-693`, `:706-731`. The branch, HEAD, upstream and cleanliness checks run concurrently. A slow status walk can leave a substantial interval after `symbolic-ref` and the occupancy check have finished. If another writer switches to a clean branch at the same old commit in that interval, Git fast-forwards the branch now checked out. The after-read can report uncertainty; it cannot undo the wrong move. Similarly, if another writer advances the original branch to the target, Sync can report `moved: facts.behind` for its own no-op. The lock at `:1294-1297` is keyed by project, not checkout, and does not coordinate terminal Git. Move slow reads before the final identity/occupancy checks, serialize app writers by physical checkout, and make the update conditional on the expected branch and old tip at write time. If that cannot be guaranteed for a writer, distinguish an observed end state from a move attributed to Sync. Add an interleave at merge entry, not only inside `ls-remote`.

## P2-44 [medium] A slow repository suppresses healthy repositories

`apps/server/src/fleet/projectSyncOrigin.ts:77-82`, `:105-120`; `apps/server/src/fleet/ProjectSync.ts:454-470`. A timeout on one large repository closes the hostname for later repositories in that call, including an untried HTTPS repository when only SSH was slow. On `fetch` they get a timeout sentence without a request; on `run` they can use old offline permission instead of learning that a reachable branch was deleted. The test at `apps/server/src/fleet/ProjectSync.origin.test.ts:323-335` explicitly equates SSH and HTTPS. A healthy repository that always takes more than ten seconds to list can never get past “Sync again.” Budget the batch without treating a different repository as offline. Use the effective scheme, endpoint and repository identity for failures; distinguish skipped work from a failed request and offer a longer or targeted retry. Prefer obtaining the advertisement as part of the fetch.

## P2-45 [medium] At 2,001 remote branches, deleted-branch extras silently disappear again

`apps/server/src/fleet/ProjectSyncExtras.ts:155-156`, `:185-187`, `:206-225`. Above the cap the code throws away the entire membership map, even if the branches share one tip. A branch level when deleted then compares with its stale tracking ref and disappears, although it has a unique commit. No truncation count warns the person. Keep branch membership regardless of the command argument limit; stream exclusion OIDs to `rev-list --stdin` instead of expanding them into one argument vector. Also preserve the distinction between a branch name that exists only here and a branch with unique commits: `:210` suppresses a deleted branch with **zero** unique commits, contrary to AC-12's separate branch-name category. The equivalent never-published branch is listed at `:215-222`. The test at `apps/server/src/fleet/ProjectSync.results.test.ts:245-256` enshrines that inconsistency.

## P2-46 [high] A configured squash can stage changes on a “refused” checkout

`apps/server/src/fleet/ProjectSync.ts:710-719`, `:737-744`. Git reads `branch.<name>.mergeOptions`. If it contains `--squash`, a fast-forwardable merge can update the index and working tree without moving HEAD. The explicit `--ff-only` and `--no-autostash` do not negate squash. The unchanged HEAD is then reported as a refusal although the checkout now contains staged changes. This contradicts AC-11's unchanged index and working tree for a repository that did not fast-forward. Neutralize branch-specific merge defaults or decline before mutation; at minimum explicitly override squash. Test the returned step **and** index and file contents. The installed Git manual confirms both option semantics; this configuration was not executed.

## P2-47 [medium] A successful fetch can be reported as a failed fetch

`apps/server/src/fleet/ProjectSync.ts:479`, `:491-492`, `:999-1015`. A fetch updates the tracking refs, then a local branch read times out. The fallback discards the proof and sets `fetch: "failed"`. The focused test at `apps/server/src/fleet/ProjectSync.origin.test.ts:689-699` deliberately injects this *after* the real fetch and expects `fetch-failed`. The other repositories survive, but the person is told the wrong operation failed. Preserve the completed fetch status; independently report “fetched, but could not read the checkout” and prohibit a move.

## P2-48 [medium] A nested checkout probe can still discard the entire batch

`apps/server/src/fleet/ProjectSync.ts:273-281`, `:299-302`, `:1207-1211`, `:1283-1289`. A timeout starting or running the linked-worktree check for one discovered nested repository rejects `repositories()` before the per-repository `fetchAll` handler starts. The project returns no facts, even for its root. A nonzero Git exit instead looks like “not a linked worktree”, which is not established either. Keep the failed path as unread/skipped, never move it, and continue the other paths. Test through the service discovery boundary, not just by passing preconstructed repository arrays to `fetchAll`.
