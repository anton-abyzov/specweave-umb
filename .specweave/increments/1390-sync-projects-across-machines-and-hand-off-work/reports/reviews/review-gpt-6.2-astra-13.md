## Blocking findings

### R6-01 [high] The new offline check admits Git versions and configurations that still fetch

**AC-11 promise 2.** `apps/server/src/fleet/projectSyncMove.ts:207-217` approves every Git at or above 2.45 without inspecting the repository. On **2.45.0**, `GIT_NO_LAZY_FETCH` disables ordinary missing-object lookup, but not checkout's direct prefetch. A clean blob-filtered checkout can have the target commit and trees but lack an ordinary file's new blob. The move reaches `read-tree -u` at `apps/server/src/fleet/projectSyncMove.ts:392-405`, and Git requests the blob from origin during `run`. This is not a request for origin's *latest* branch; even a request for the approved blob violates the offline promise.

The distinction is visible in Git's tagged sources: [2.45.0 reads the environment flag](https://github.com/git/git/blob/v2.45.0/environment.c#L208-L213), [checkout calls prefetch](https://github.com/git/git/blob/v2.45.0/unpack-trees.c#L470-L475), [prefetch calls the promisor directly](https://github.com/git/git/blob/v2.45.0/read-cache.c#L3736-L3755), and [the promisor starts a fetch](https://github.com/git/git/blob/v2.45.0/promisor-remote.c#L17-L35). [2.45.1 checks the flag in that last path](https://github.com/git/git/blob/v2.45.1/promisor-remote.c#L27-L34). There is also a hole below the cutoff: [Git 2.44 registers `remote.<name>.partialclonefilter` alone as a promisor](https://github.com/git/git/blob/v2.44.0/promisor-remote.c#L129-L142); the new two-key regexp misses it.

**Fix:** prohibit Git transport for the local move, including its initial object reads, or decline all partial clones until direct prefetch is known to honor the guard. If using a version/configuration check, include patch level and filter-only remotes, and put it before `checkAsFetched` peels `HEAD` (`projectSyncMove.ts:292-296,431-434`). Test an actually missing blob and observe transport requests from Git's children, not just commands the service starts. The 2.45.0 positive test currently requires success with all objects present.

### R6-02 [high] The new writer binds to a trimmed directory name, not necessarily the Git directory that fetched

**AC-11 promises 1 and 5.** `apps/server/src/fleet/projectSyncGit.ts:96-99` trims the entire output of `rev-parse`; `apps/server/src/fleet/projectSyncFacts.ts:267-280` takes the second line as the Git directory. Previously this string was used for comparison. Now it is the `GIT_DIR` passed to the reader, ref transaction, tree writer and readback (`apps/server/src/fleet/projectSyncMove.ts:283-296,339-346,392-405,611-615`). The final unbound check at `:515-523` uses the same lossy reader.

A separate Git directory whose basename ends in a space is valid on Unix. Suppose its sibling without that space is a copy with the same branch, old tip, upstream, target object and index. The fetch reads the real repository but records the sibling's path. Both folder checks agree on that wrong path. The guarded write advances the sibling's ref and updates the actual worktree's files; readback from the sibling can report a verified count while the actual checkout's branch is still at its old tip. **No concurrent writer or folder substitution is needed.** Git [retains trailing spaces in a gitfile path](https://github.com/git/git/blob/v2.50.1/setup.c#L963-L975) and [prints the canonical directory followed by a newline](https://github.com/git/git/blob/v2.50.1/builtin/rev-parse.c#L1036-L1044).

**Fix:** read each path separately, losslessly. Remove only Git's terminating newline, reject undecodable or ambiguous output, and use that exact verified directory for the transaction and readback. Add a matching-sibling test that checks both actual refs and indexes; refusal before any write is also acceptable.

### R6-03 [high] Hidden-ref cleanup verifies an OID, not which repository and ref it is deleting

**AC-11 promise 6.** `apps/server/src/fleet/ProjectSyncExtras.ts:415-432,452-460,559-562` remembers the OID after exclusive creation, awaits peer work, then opens the repository again by worktree path and deletes the ref with Git's default dereferencing behavior. If the hidden name has become a symbolic ref to a branch at that OID, the comparison succeeds and Git deletes the **branch**, which this call never wrote. Git's [own ref tests distinguish dereferencing deletion from deleting the symbolic name](https://github.com/git/git/blob/v2.50.1/t/t1400-update-ref.sh#L192-L208). Separately, if the checkout now opens a different Git directory containing a same-name, same-OID ref, cleanup can delete that repository's ref instead. The expected OID matches in both cases.

**Fix:** confine temporary refs to storage owned by the send, or pin the repository for the whole send and use a unique per-invocation direct ref with non-dereferencing, identity-checked cleanup. Leave anything whose ownership can no longer be proved. Apply the same rule to branch and snapshot sends. Test that the other branch and the ref in a replacement repository both survive; checking only that the original temporary name disappeared is insufficient.

## Follow-up (non-blocking)

1. **F-01: a copied staging mark is still deletion authority.** `cloneStaging.ts:71-91,104-110` validates the token's shape, not its association with this directory. `ProjectSync.ts:115-127` recursively removes a qualifying copy when the marked owner is gone, or is this process but the path is not a live clone. A renamed backup containing a copied mark can therefore be erased. This is a data-loss risk, not merely untidy staging; it is separate from the six fast-forward/ref promises. Bind the mark to the original directory identity or leave unproven folders for manual cleanup.

2. **F-02: a local-only branch can still disappear from inventory.** In `ProjectSyncExtras.ts:246-257,275-287`, a local branch tracking another local branch at the same tip takes `continue` with zero commits before checking its name in the fetched origin heads. If origin lacks that name it is nevertheless omitted. Determine exact-name membership before selecting the comparison upstream.

3. **F-03: some unread reasons still disappear.** In `projectSyncFacts.ts:172-180,189-190` a failed settings/folder read returns `not-run` without a row. If discovery succeeds on `run`, `projectSyncMove.ts:253-259` reports no fetch rather than the earlier read failure for the valid ID. Also, `packages/contracts/src/projectSync.ts:403-407` appends the unread sentence to an error that can already be 1,900 characters (`projectSyncGit.ts:101-108`), then truncates it away. Retain refusal-only records without requiring a usable binding, and reserve room for both reasons. Neither case authorizes a write.

4. **F-04: the finish deadline ends before the process has finished.** `refTransaction.ts:94-97,121-126,139-149` clears the commit timer on the acknowledgement and then awaits child close without a deadline; abort uses that same unbounded close. A child that acknowledges but stalls before exit can hold the project request. Bound the exit/abort wait after the tree writer has settled, not the time spent writing the tree.

5. **F-05: shared path decoding is not lossless for all readers.** At `folderTransfer/git.ts:34-41`, the new fatal decoder removes a leading UTF-8 BOM from otherwise valid output. A first NUL-separated pathname starting with U+FEFF becomes a different name. The older `Buffer.toString` preserved it. `ProjectSyncExtras.ts:103-126,212-223,298-306` also consumes name lists without checking the new `invalidUtf8` flag. Preserve the BOM as data and treat an undecodable list as unread at each path/ref consumer. The R5-05 move test is not coverage for snapshot or inventory lists.

6. **F-06: diagnostic stderr is not proof of commit refusal.** `refTransaction.ts:76-86,94-106` discards the exit status/signal and treats any accumulated stderr without `commit: ok` as refusal unless its own timer fired. `projectSyncMove.ts:620-626` then says another program moved the branch. If Git published the ref but died before acknowledgement after printing a warning, that attribution is unsupported even though the count is withheld. Keep ambiguous termination as lost; only state refusal on affirmative evidence.
