## [medium] apps/web/src/components/studio/ProjectMachinesSettings.tsx:365 Settings lost its revive button on every current machine · can follow
The renamed "Continue the coordinator here" in Settings renders only under `availability && !machines.startReady(...)`. `startReady` is ready plus the `coordinatorPerMachine` capability (`apps/web/src/components/studio/useLinkMachines.ts:63`), which the current server always advertises (`apps/server/src/environment/ServerEnvironment.ts:389`). Before this PR that gate chose "Start a coordinator here" over the takeover on modern machines; D-06 removed Start and kept the gate, so the row now shows neither. Scenario: the coordinator's machine has been silent 12 minutes, the person opens Settings > Project > Machines on m5 (the surface Wording table 5 renames this button on) and finds only Unlink; the working path is the project page's menu/message box, which they have to discover. Fix: drop the `!startReady` condition at line 365 and add a test with `state.perMachine` set asserting "Continue the coordinator here" is present (the new test at `ProjectMachinesSettings.test.tsx` asserts Start is absent but not that Continue is present).
