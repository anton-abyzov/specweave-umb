## R9-01 [high]: Cleanup can remove a replacement directory's refs

**AC-11 promise 6: “Sync deletes only refs it wrote itself in that same call.”** `apps/server/src/fleet/ProjectSyncExtras.ts:629-632` retains the pathname returned by `mkdtemp`, not the directory's identity or an ownership marker. Both normal completion (`:587-590`) and failed initialization (`:654-657`) recursively remove whatever real directory that pathname names at cleanup time. The only `lstat` is **after** removal.

**Scenario:** The send is waiting for its peer. Its temporary volume or staging parent is restored, and the same pathname now contains a different real directory with a bare repository. Cleanup removes that repository's refs along with its other contents, including any branch this send never wrote. A random name prevents an initial collision; it does not distinguish an original from a restored copy. This does not depend on recursive removal following a symlink at the final path. Restoring only the source checkout under an otherwise stable system-temp root is safe and is what the green tests cover.

**Fix:** Put the private repository under an owned, marked staging root and bind removal to the directory created for this send. If cleanup cannot establish that identity for the actual removal, leave the directory and report it. A pathname check followed by the same unconditional recursive remove just narrows the race. Acceptance: replace the disposal target while the peer is held; on both success and refusal, a foreign ref and an unrelated sentinel in the replacement must survive. This finding is about the new sender disposer, not the existing clone sweeper.

## Follow-up (non-blocking)

1. **The requested `GIT_DIR` is not always the effective ref store.** `apps/server/src/fleet/ProjectSyncExtras.ts:437,445-446,635-646`, `apps/server/src/handoff/checkpointGit.ts:144,352-356`, and `apps/server/src/fleet/folderTransfer/git.ts:61-72`: private operations override `GIT_DIR` but inherit `GIT_COMMON_DIR`. In two disposable bare repositories, a read-only Git path query with the private Git directory and the source common directory resolved both the exact hidden ref path and `config` under the **source**. A private init or publication can therefore affect the source; deleting the temp directory cannot undo a ref published there. This is a real isolation gap, but a stray ref is not itself a deletion under promise 6. Clear repository-location overrides for private commands, consistently through checkpoint publication and bundling, and assert the effective common directory and unchanged source config/refs.
2. **The snapshot is not protected from source-side prune.** `apps/server/src/handoff/checkpointGit.ts:253-257,338-355` writes the blobs, tree and commit into the source. `apps/server/src/fleet/ProjectSyncExtras.ts:470-481,517,552-561,647-650` roots the snapshot only in the private repository, which borrows objects in one direction. In a disposable graph, Git listed the snapshot under the private refs but classified the same commit as unreachable in the source. An immediate external prune during negotiation can make the send fail; the source worktree is not deleted and the sender returns `stays`, not `sent` (`:570-584`). The trace tests at `apps/server/src/fleet/ProjectSyncExtras.round8.test.ts:302-314` passed on **both** versions: they show that the sender does not launch maintenance, not that an independent prune is safe. Write new objects into the private store from the start, and retain any otherwise unrooted borrowed history needed until the bundle is self-contained.
3. **Some valid configuration counts still lose entry zero.** `apps/server/src/fleet/projectSyncGit.ts:59-76` accepts only one to four decimal digits. With `GIT_CONFIG_COUNT=00001`, `+1`, or a space followed by `1`, local Git 2.50.1 read entry zero in all three cases; `moveEnv` treats each as zero and overwrites it. An inherited `safe.directory` can consequently work at fetch and disappear during the move. Match Git's count semantics or decline an unsupported representation without silently rewriting the list.
4. **SHA-1 is assumed to be the default for new repositories.** `apps/server/src/fleet/ProjectSyncExtras.ts:618-621,635-645` reads the source format but omits `--object-format` when it is `sha1`. With `GIT_DEFAULT_HASH=sha256`, a disposable SHA-1 source and the same private init produced `sha1` and `sha256` respectively. The private repo cannot use that source's object IDs; a send that used to work stays instead. Pass the measured format explicitly for both algorithms. This is a refusal, not an unsafe move or deletion.
