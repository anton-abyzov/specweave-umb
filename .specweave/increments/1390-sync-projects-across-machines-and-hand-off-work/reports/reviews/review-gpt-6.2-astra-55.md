**What needs to change:** Refuse a Git operation unless its working-tree and administrative writes can be confined. Replace worktree pointers by name from a fresh private file, rather than modifying a possibly shared inode. Bind approval and retries to the target identity and expected contents. Under a verified parent, create each missing component with private access and verify it before using it. Treat an unknown ACL or volume rule as unsafe. Remove the out-of-target probe rather than relying on its cleanup.

## Verified controls and their limits

**Manifest paths.** `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/paths.ts:15–47` rejects slash-rooted paths, empty components, `.` and `..`, control characters and components over 255 UTF-8 bytes. Windows additionally rejects colon/stream and backslash forms, trailing dots/spaces and the listed device names. `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/manifest.ts:1112–1152` checks each prefix for colliding spellings and rejects entries below an explicitly declared file or link, independent of manifest order. NFC and lowercasing catch the common aliases only when the assumed naming rules fit. A copied link is not itself proof of a write through it. Validating each size as a nonnegative safe integer does not establish AC-25's approval-fixed aggregate staging limit.

**Root anchoring and mutation checks.** The ordinary POSIX sticky exception at `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/confinement.ts:317–343` requires a root- or app-owned ancestor and an existing app-owned directory next. An untrusted sticky owner or missing next component does not qualify. Descendant symlinks are refused. The ancestor walk has a distinct limit at lines 374–385: it normalizes link text lexically before walking it. Parent traversal after an intervening symlink can resolve differently in the kernel; reject ambiguous link ancestry rather than certifying it. At `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/apply.ts:443–468,549–559,738–740`, each ordinary file action, not just the first in a batch, gets a before/after chain check. Preflight records the folder and reason, and a detected post-action identity change stops and reports landed entries. This does not cover every individual create, rename, delete, write and mode change within an action. A stop after an outside mutation cannot make the outside-file guarantee true.

**ACL evidence.** Windows runs PowerShell `Get-Acl -LiteralPath` for SDDL, obtains the current SID from `WindowsIdentity.GetCurrent()`, and uses `Get-Item` attributes to reject `FILE_ATTRIBUTE_REPARSE_POINT`. A missing row fails as `acl-unreadable`; a parseable-looking but unsafe descriptor can pass (finding 4). macOS parses `/bin/ls -lde`; a missing heading fails, but a heading without a successfully parsed ACL is accepted, and the subprocess exit status is discarded. Linux assumes group mode bits bound all ACL grants. That works for the POSIX access-ACL group mask, not as proof for every mounted filesystem's delete and permission-change semantics. Where those semantics are unknown, the product must refuse rather than infer privacy. See `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/confinement.ts:81–87,152–194,199–251,320–343`.
