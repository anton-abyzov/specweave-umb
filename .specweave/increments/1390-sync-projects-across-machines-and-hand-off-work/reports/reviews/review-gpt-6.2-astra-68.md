## New blocker: repair can replace a pointer outside the approved tree

**High.** A copied linked worktree may have ordinary file entries but a repository header that identifies an unrelated, user-owned main repository outside the target. The manifest check validates entries, not the header's repository paths (`/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/destinationService.ts:1071–1092,1287–1300`). The planner permits a copy when the header has no matching main plan (`/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/reconcile.ts:371–374,398–408`), and Apply passes that metadata to repair (`/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/apply.ts:882–893`). Round 1 used the checked `absoluteIn` resolver for the main repository (`/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/apply.ts:1093` at `12416a760ff49134c6480859ac6e54bbae76b655`). The new helper joins path components without that check. If the unrelated repository has the matching private worktree record, all ownership checks can pass and the explicit rename changes its `gitdir` file (`/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode/apps/server/src/fleet/folderTransfer/worktreeRepair.ts:31–57,73–86`). This needs neither a race nor a hard link. It is an additional regression, not another count of the old hard-link write.

**Fix:** Reject invalid repository-header paths before staging. At repair time independently validate both paths beneath the pinned target and require the admin record to belong to the approved main/worktree pair. Replace only the two verified names; do not invoke a broader repair unless all its writes are proven confined. Add a refusal test that also asserts the unrelated record's bytes are unchanged.
