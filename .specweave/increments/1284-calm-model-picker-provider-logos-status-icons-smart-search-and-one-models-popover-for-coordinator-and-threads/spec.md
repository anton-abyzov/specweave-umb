# Calm model picker: provider logos, status icons, smart search and one Models popover for coordinator and threads

Mockups (before and after, dark and light): `/Users/antonabyzov/.specwithcode/m4/evidence/picker-redesign-20261110/mockup.html`

## Problem

Anton, November 10, 2026: the model picker is "overcrowded with text", "it's not clear what we are choosing", search for "carbon" doesn't make the match stand out, and it's not obvious which machine runs a coordinator or thread. Evidence from source (`specwithcode-dev`, main) and his five screenshots:

- **Rows repeat text.** Each provider row prints up to three lines: a truncated provider name ("Copilot Enterprise (abycras…"), a usage line ("Usage not read") and a facts line that starts with "Billing unverified" whenever billing is unknown (`apps/web/src/components/chat/HarnessDescription.tsx:16`, `apps/web/src/studio/modelAvailability.ts:511,530`). The file's own comment says missing telemetry is not a negative capability, yet the row prints it on every line. Each row also repeats the effort ("Medium"), a ⌘N badge and a star. The header "Account limits:" band is three lines of colored prose.
- **Search shows non-matches.** `scoreModelPickerSearch` (`modelPickerSearch.ts:36-48`) scores every token against six fields, the last being name, driver and provider display name joined, and allows subsequence fuzzy on all of them for tokens of 3+ characters. A loose subsequence hit on a long provider name is the most likely reason "carbon" lists Opus 5.5, GPT-5.3-Codex and Fable 5 under Gemini 4 Carbon at the same weight. Nothing is highlighted, there are no aliases beyond the catalog's, and no capability words ("cheap", "fast").
- **Cursor shows 0 and doesn't say why.** On M4 the Cursor provider is enabled but signed out (`~/.specwithcode/m4/caches/cursor.json`: `auth.status: unauthenticated`, "Sign in with Cursor or add CURSOR_API_KEY", 0 models, checked November 10, 6:39 PM). `checkCursorProviderStatus` returns no models without a key (`CursorProvider.ts:271-287`), and the rail hides the count when it is 0 (`ModelPickerProviderChips.tsx:84`). Carbon in the screenshot comes from Copilot Enterprise. Carbon under Cursor needs a Cursor sign-in on this machine (1277 T-05).
- **What is being chosen is unclear.** The chip under the coordinator composer opens the same picker used everywhere, with no title. It sets only the coordinator model (`CoordinatorModelPicker.tsx:386`). The model threads run on ("Recommended model for threads") and their effort live in Project settings (`ProjectWorkspaceSettings.tsx:527-546`), two clicks away.
- **Coordinator effort is fully open.** The picker's effort strip and the control beside the chip let the coordinator run at any level the model lists, Low through Max (`CoordinatorModelPicker.tsx:279-290,468-481`; only Ultrathink is excluded). The only default is Medium on Opus 5.5 when nothing is chosen (`packages/shared/src/coordinatorDefault.ts:257-271`); other models take the provider default. Anthropic's Claude app shows models only: "The coordinator runs at a fixed effort to route requests and answer responses most efficiently." The coordinator re-reads a large context every turn and its job is routing and replying; high effort makes replies slower and spends the weekly window that workers need.
- **Machine identity is a small grey chip.** Nicknames exist (`machineNicknames` setting keyed by environmentId, `packages/contracts/src/settings.ts:333-341`, synced by `MachineNicknameSync.ts`), but there is no color or icon per machine, and the composer looks the same whichever machine will run the turn.
- **The composer has a permanent footer line**, "Additional folders are available with Codex, Claude and Muse Code." (`CoordinatorModelPicker.tsx:512`), and chips that spell everything out ("Claude Code · Opus 5.5 5%").

## Scope

In:
- Picker rows: provider logo as the identity, one line per provider, status as icons with tooltips, a one-line limits strip.
- Search: matches only, highlighted, ranked; aliases and capability words; typo tolerance only as a labelled fallback; a signed-out provider that would have the model is offered as "Sign in".
- A Models popover on the coordinator chip: Coordinator model, Model for new threads, Effort for new threads, in one place; the picker it opens says what it is choosing.
- Coordinator effort: Medium by default, capped at High, no effort control in the composer.
- Machine identity: color and icon per machine, on the composer, machine chip, thread header and sidebar rows; the target machine's color before sending to another machine.
- Composer chips calmed the same way; the permanent footer line removed.

Out:
- Model tiers, the fallback chain, effort value mapping, the "Extra" label, Ultrathink placement, Fast and Ultracode chip behavior and the follow-project record. The thread "Default model for all projects" owns those; this design uses its labels and its single project store.
- Cursor billing labels and prepaid credit (1277).
- The iPhone picker (1273) and mobile composer.
- A release (the "Release all platforms" thread owns it).

## Approach

Order: search (pure, testable), rows, popover, effort cap, machine identity, composer. Each is its own PR to `anton-abyzov/specwithcode` main.

**Search** (`apps/web/src/components/chat/modelPickerSearch.ts`, new `packages/shared/src/modelSearchIntents.ts`). Split fields into name fields (name, shortName, aliases, manifest `searchAliases`) and provider fields (driver, display name, vendor words). Drop the joined-text field and `fuzzyBase` from provider fields. Return match ranges with the score so `ModelSearchGroupRows.tsx` can highlight. Capability words map to predicates over `ServerProviderModel` (`billing`, `contextWindow`, `imageInput`, option descriptors) and the tiers from `modelTiers.ts`; "cheap" and "smart" need a small `sizeClass` per family in `model-manifest.json` because no price is in the contract. Typo fallback is a bounded Damerau-Levenshtein over name words, used only when the direct pass is empty. First task: a test reproducing the screenshot ("carbon" against Copilot Enterprise and personal catalogs) to confirm the cause before changing it.

**Rows** (`ModelListRow.tsx`, `ModelSearchGroupRows.tsx`, `HarnessDescription.tsx`, `ModelUsage.tsx`, `ModelStateTag.tsx`, `ModelPickerContent.tsx`). `describeModelFacts` stops returning "Billing unverified"; a new `modelStatusIcons(model, availability)` returns the icon list for AC-02, and the long sentences become tooltip text. Icons are Lucide (`Coins`, `HardDrive`, `CircleSlash`, `CircleDashed`) plus the existing usage ring and provider logos in `Icons.tsx`; no generated icons are needed. `ModelPickerContent.tsx` is at 1,534 lines, over the 1,500 limit, so the limits strip and the titled header move into their own files.

**Models popover** (new `apps/web/src/components/studio/shell/ProjectModelsPopover.tsx`, `CoordinatorModelPicker.tsx`, `ProjectWorkspaceSettings.tsx`). The popover reuses `ProjectModels` state and `useCoordinatorModelSave`; the thread model and effort write the project store the other thread is making single (Settings copy). The picker gets a `title` prop.

**Coordinator effort** (`packages/shared/src/coordinatorDefault.ts`, `ProjectCoordinatorService.ts`, `ProjectSettingsNormalizer.ts`). `defaultModelOptions` gives Medium to any coordinator model that lists it, not only Opus 5.5. A new `capCoordinatorEffort` clamps at turn selection, so saved settings are not rewritten and lifting the cap later needs no migration.

Recommendation and why: **default Medium, cap at High, hide the control.** Fixed Medium like Anthropic is the right default, since the coordinator routes and replies and hard work goes to threads. A hard fix removes the one useful exception, a coordinator on a small or non-Claude model that needs High to route well, so High stays reachable in Advanced. Max and Extra on a coordinator only buy slower replies and a faster-draining weekly window.

**Machine identity** (`packages/contracts/src/settings.ts`, `packages/shared/src/machineNicknames.ts`, `apps/server/src/fleet/MachineNicknameSync.ts`, `apps/web/src/studio/machineNickname.ts`, new `apps/web/src/studio/machineIdentity.ts`, `RenameMachineDialog.tsx`, `EnvironmentMachineIcon.tsx`). `MachineNickname` gains optional `color` (a palette id, not a hex, so each theme maps it to tokens that pass contrast) and `icon` (an `EnvironmentMachineKind`). Merge stays last-writer-wins on the whole entry. An older peer decodes the entry without the new keys and could send it back stripped, so the fields sync only with peers reporting a new `machineIdentity` capability, and a merge never drops a color for an entry with the same stamp. Default color: hash of environmentId into the palette, stepping past colors already taken.

**Composer** (`CoordinatorModelPicker.tsx`, `composerModelDisplay.ts`, `modelChipFit.ts`, `ChatView.tsx` send target). The fold order from the other thread's chip fix (machine chip shrinks first) is kept; this adds the icon forms and the target color.

Rejected: a second, separate "coordinator picker" component (two pickers drift); hex colors per machine (fail contrast in one theme); coloring the whole composer background (reads as an error state and fights the theme); hiding effort for the coordinator with no override at all (see above); AI-generated status icons (Lucide covers every state, and generated icons would not match its stroke grammar).

Risks: capability words depend on a hand-kept `sizeClass`; a new family without one simply doesn't match "cheap" or "smart". Hover-only ⌘N and star reduce discoverability on touch, so on coarse pointers the star always shows.

**Usage surfaces, round 2 (Anton, November 12, 2026).** "This pop-up doesn't seem scrollable... make it consistent and sleek... which subscription it is for and which email... minimize text, icons where possible... where it's coming from, the AI provider by images." Audit of main after #152: AC-01 and AC-15 were partial (the group header prints "usage not read" via `modelAvailability.ts:511,584`; the chip prints the unknown text via `ModelUsage.tsx:492-496`), the same unknown state has five names, and only ChatGPT has a usage link (`packages/shared/src/usageLimits.ts:27`). New shared pieces: `packages/shared/src/providerUsageLinks.ts` (provider kind to usage URL) and `apps/web/src/components/usage/AccountHeader.tsx` (logo, plan, email, link), reused by every surface.

## Decisions

### Asked
- none
### Defaulted (change any before sw-do)
- D-01: Coordinator effort is Medium by default, capped at High, override only in Project settings > Advanced → matches Anthropic's intent, keeps one escape hatch.
- D-02: Unknown billing shows no icon and no text in the row → missing data is not a warning; it stays in the tooltip.
- D-03: Lucide icons and existing provider logos only → consistent stroke; no generated icons.
- D-04: Machine color is a palette id from eight hues, stored with the nickname → contrast-safe in both themes, reuses the nickname sync.
- D-05: The Models popover edits project settings, not the current thread → one meaning for "the project's models"; a thread's own model stays in its composer picker.
- D-06: Typo tolerance only when nothing matches directly → a search for "carbon" never lists near-misses.
- D-07: Search aliases, size classes and "known to offer" families live in `packages/shared/src/modelSearchIntents.ts`, not `model-manifest.json` → the manifest is fetched from main by released apps, so its schema stays as it is.
- D-09: Usage links are a fixed map of the providers' own public pages, opened in the system browser; no account id is put in the URL → nothing private leaves the app.
- D-08: No `machineIdentity` capability flag → the merge itself never drops a color or icon (same stamp, or a newer rename that states none), which covers an older peer without new plumbing.
### Open
- The fallback rank mark in `AccountHeader.tsx` is a focusable span with `aria-label` but no role, so screen readers may read only the number (review r1 finding 3, not fixed in #219). Give it `role="img"`.
- Fallback cards in Limits by account show a numbered badge but no provider logo.
- Settings > Machines still shows "Account not reported" (AC-21).
- The movable thread's "Runs on" dropdown chip has no narrow-width screenshot; its chevron may clip at the minimum width (PR #235 review round 4).
- Short labels are unique only among machines a device knows, and follow each device's name for a machine without a nickname.
