# PR 152 ship review at `62ead7a514`

Two blocking defects, five medium, and a set of low ones. Each line below was re-opened at the head; the search regression I also ran myself, head against base.

## Blocking

1. **A newly picked coordinator model does not get Medium or the High cap until the server restarts.** `packages/shared/src/coordinatorDefault.ts:324-325` returns the selection untouched when no effort is saved. Picking a model saves none (`apps/web/src/components/studio/shell/CoordinatorModelPicker.tsx:288`, `apps/web/src/components/studio/ProjectModels.tsx:106`). The Medium default is only added by the startup normalizer (`apps/server/src/project/ProjectSettingsNormalizer.ts:218`, called from `serverRuntimeStartup.ts:712`). The turn path only caps (`apps/server/src/project/ProjectCoordinatorService.ts:246`, `:419`). Opus 4.7's manifest default is `xhigh` and Sonnet 5's is `high`, so a coordinator switched to Opus 4.7 runs at Extra High with no "capped" note. AC-11 fails in the normal flow. Main behaves the same after a model change, so this is a missed requirement, not a regression.

2. **Search regression: a spaced version query finds nothing when the model name glues the version on.** `apps/web/src/components/chat/modelPickerSearch.ts:66-75` only accepts exact, prefix, word-start or compact-prefix matches. The typo fallback refuses version tokens (`packages/shared/src/modelSearchIntents.ts:310`). At head, "qwen 3", "qwen 2.5", "llama 3.2" and "seek" return no models; base returned `Qwen3 Coder`, `qwen2.5-coder:7b`, `llama3.2:latest` and `DeepSeek-V3.1`. The repro harness is in `/tmp/pr152-review/scratch/area4/run.ts`.

## Medium

3. **The Models popover cannot be scrolled when it is taller than the window.** The scroll lock cancels wheel and touch outside `[data-model-picker-content]` (`apps/web/src/components/chat/ProviderModelPicker.tsx:237-251`). The new front view root lacks that attribute (`apps/web/src/components/studio/shell/ProjectModelsPopover.tsx:147-153`).
4. **From a phone or any non-loopback browser, every thread shows the colored composer and "Send to <machine>".** `apps/web/src/components/ChatView.tsx:5068-5073` keys on `isThisMachineTarget`, which is true only for loopback (`apps/web/src/connection/desktopLocal.ts:57-61`). The window tint treats that same primary as this window's machine (`apps/web/src/components/MachineWindowTint.tsx:12`). This contradicts AC-14.
5. **A name-only rename pins the icon and color.** `apps/web/src/components/settings/RenameMachineDialog.tsx:87` always writes both, and `apps/web/src/studio/machineIdentity.ts:86` prefers the pinned icon. The separate Icon menu then changes Settings and Run on but not thread rows or the sidebar. Nothing returns either value to automatic.
6. **The cap leaves Claude's Ultracode toggle on.** `coordinatorDefault.ts:333-337` rewrites only the effort option; `ultracode` is a separate boolean (`apps/server/src/provider/ClaudeModelCatalog.ts:66-71`) and Advanced still offers it.
7. **Default machine colors depend on which machines a device knows.** `machineIdentity.ts:73-74` feeds connected machines into `assignMachineColors`, so the tint can change when another machine connects and can differ between devices.

## Low

- **Real account names in a public repo (your rule 6):** the PR adds 8 lines with `abycrash`, `abycrash-robotics-on`, `abycrash-corp` and `anton-abyzov`, for example `apps/web/src/components/chat/modelPickerSearch.test.ts:40-41`. `abycrash` is already on main elsewhere, and the fixture uses a placeholder.
- **Blocked reason is hover-only:** `apps/web/src/components/chat/ModelListRow.tsx:160` keeps `warningReason` only as sr-only, so touch and keyboard users lose the reason and exact reset time that base printed.
- **Pi coordinators get a duplicate `thinking` option** (`"medium"` plus `true`) from `coordinatorDefault.ts:268-275`. The adapter reads the first, so it runs at Medium.
- **Capability chip needs two clicks** when the query holds two synonyms such as "image vision" (`modelSearchIntents.ts:85`, `ModelPickerContent.tsx:1210`).
- **Signed-out providers on the search rail are disabled with no Sign in action** (`apps/web/src/components/chat/ModelPickerProviderChips.tsx:178`); AC-08 asks for one there.
- **Hard-coded English strings:** new status and strip text bypasses `tx`, and the translated "New model" label regresses (`apps/web/src/components/chat/modelStatusIcons.tsx:65`).
- **Nickname merge can settle on an older color:** an older build's rename in between, or a future color id, lets the tie-break pick the stale value (`packages/shared/src/machineNicknames.ts:46-49`). Machines still converge, with no write loops.
- **Stale manual script:** `apps/web/tests/picker-usage/verify-1054.mjs:259` still expects "Account limits:", which this branch removed. It is not in CI.

## Checked and sound

- **Cap mechanics:** no model selection churn per turn, and fallback and off-pick detection compare only instance and model. Workers are untouched, and the normalizer is idempotent.
- **Merge of main:** none of the 321 files main changed since the fork appears in the PR diff. The `ChatView.tsx` diff is 26 added and 3 removed lines once whitespace is ignored. `backgroundWork` survives next to `title`, `titleContext` and `onBack`.
- **Nickname decoding:** unknown color or icon values decode as absent, and older peers that strip the fields no longer erase a color.
- **Window tint:** fixed, `pointer-events: none`, z-index 2147483000, no layout effect, light and dark rules, hidden in print (`apps/web/src/index.css:2656-2679`).
- **Size and hygiene:** `ModelPickerContent.tsx` is 1,499 lines. The 11 commit subjects are short with no AI references. No secrets or personal paths; `axe-core` is a dev dependency only.

The review used 10 agents, which ran on this session's model because the Workflow tool has no model selector. The run was cut off once and resumed from its cache.

VERDICT: DO NOT SHIP 62ead7a514

Two real defects would reach users. A coordinator model picked from the new popover runs at the provider default, Extra High on Opus 4.7, until the next server restart, so the Medium default and High cap do not hold in the normal flow. Search now returns nothing for "llama 3.2" or "qwen 3", which main finds. Neither loses data, and the first is no worse than main today. Both fixes are small: apply the coordinator defaults before the cap in `turnSelection` and `ensure` (or on save), and let a name token match a glued version. While the branch is open, add `data-model-picker-content` to the popover root, compare the send target to the window's primary environment id, and replace the real account names in the four test files. The merge of main is clean and the tint is safe. The remaining findings can follow in a later change.
