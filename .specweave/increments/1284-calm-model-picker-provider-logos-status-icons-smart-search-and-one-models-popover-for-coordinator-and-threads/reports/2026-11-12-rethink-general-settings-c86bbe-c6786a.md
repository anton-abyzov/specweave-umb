**Why Devin wins over your Claude Code subscription**

I checked the stored settings on this machine (`/Users/antonabyzov/.specwithcode/m4/userdata/settings.json`) and the resolution code in `/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev`:

1. There is no explicit default stored where workers look. The machine-level `defaultModelSelection` is absent, and this project's override (`1332065e-795b-4f98-91c4-f114917e53f6`) holds only `defaultThreadEnvMode` and a fallback list (Claude Opus 5.5, then GPT-6.1 Sol). No `defaultModelSelection`. Whatever you picked in the UI, it did not land as the project's or the machine's worker default.
2. The delegate path deliberately discards a machine default anyway. [ProjectDelegation.ts](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/server/src/project/ProjectDelegation.ts:20) `projectWorkerModel` returns a model only when its source is the project itself; a machine-level choice resolves as source `environment` and is dropped to null, "so a project that never chose a model keeps lanes and Auto."
3. Null falls to the automatic host pick. [coordinatorDefault.ts](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/packages/shared/src/coordinatorDefault.ts:173) `defaultWorkerModelSelection` prefers Claude, but only among providers where `canTakeTurn` is true. Your screenshot shows Claude Opus 5.5 as "Usage full," so Claude is filtered out entirely, and the first other ready, non-per-token provider in server order wins. `acpRegistry_devin` is a configured instance on this machine, so Devin is a legitimate candidate in that scan, including with unknown billing.
4. Two more silent moves can follow. [WorkerLaunchRoom.ts](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/server/src/project/WorkerLaunchRoom.ts:34) moves a worker off a full preferred provider to the same model elsewhere, the coordinator's model, or the fallback order, and Auto/lane routing can move it again when the project has no model of its own. The only trace is a server log line and a "stands in for" marker.
5. The UI hides all this. In [ProjectDefaultsSettings.tsx](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/web/src/components/settings/ProjectDefaultsSettings.tsx:124) the picker displays `resolveDefaultProviderModelSelection(providers, settings.defaultModelSelection)`, which, when the stored value is null, renders the first ready provider as if it were chosen; "Automatic" is one small status word at line 290. You can look at a concrete Claude model in that row and reasonably believe you set it, while the store holds null and the server is free to pick Devin.

Fix direction, in order: honor a saved machine default in `projectWorkerModel` (distinguish "saved" from null/Automatic in the contract); exclude unknown-billing ACP instances such as Devin from every automatic pick, the same consent rule the reviewer order already applies at [AdversarialReviewSettings.tsx](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/web/src/components/settings/AdversarialReviewSettings.tsx:107); and when an explicit pick is full, say so on the thread ("Claude full, moved to X") instead of moving silently. This overlaps the "1284 model picker and machine colors" thread only at the picker surface; the precedence bug is server-side and belongs to whoever owns delegation, not 1284.

**Simplified reorganization**

General today is [SettingsPanels.tsx](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/web/src/components/settings/SettingsPanels.tsx:2295) at 3,881 lines with 66 `SettingsRow`s in the file, and Providers adds a 1,552-line [ProviderSettingsPanel.tsx](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/web/src/components/settings/ProviderSettingsPanel.tsx:1425) stacking provider cards, Model tiers, Regular/frontier, Adversarial review, Decision model, Usage, and Advanced in one scroll. - **Providers becomes four blocks.** Accounts (the existing provider list/editor, unchanged). Defaults: three one-line pickers, New threads / Coordinator / Reviewer, each showing "Automatic (currently: X)" when unset, which fixes the Devin surprise at the surface. - **The expanded bunch collapses to one line per primary.** Alternates become "Also on: Copilot, Cursor, Devin" as provider icons with a chevron that expands on demand; in the default order they are hidden entirely, since they are automatic. Status follows 1284's icon system (ring, slashed circle, dashed ring) instead of repeating "Usage unknown / Billing unknown" chips on all ten rows; the sentences move to tooltips. That takes the screenshot's list from ten rows to three.
- **Descriptions shrink to one line each**, with the current second and third sentences (the `REVIEWER_ORDER_DETAILS` policy text at [AdversarialReviewSettings.tsx](/Users/antonabyzov/Projects/github/specweave-umb/repositories/anton-abyzov/specwithcode-dev/apps/web/src/components/settings/AdversarialReviewSettings.tsx:45) is the pattern) behind the info icon that already exists.
