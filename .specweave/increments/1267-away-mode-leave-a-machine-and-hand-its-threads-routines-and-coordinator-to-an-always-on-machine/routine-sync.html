Routines across machines: how others do it, and what we should do

Recommendation: keep routines on your machines, replicate each definition to all of your own machines, and let exactly one machine run it. A machine that is yours can edit a routine on another machine that is yours. That alone ends the hand editing of the IG routine. No sync server, no routine files in Git, and umbrella projects are not required.

Why the IG routine is stuck both ways

Each machine treats the other as a stranger holding a grant. Check 1 is refuseGrantRoutineChange (workGrantAccess.ts:453): new grants get routines: false. Check 2 is refuseOthersRoutine (routineOwnership.ts:17): it only lets through routines the caller's own grant created, so a routine you made by hand is off limits even with routines on. Nothing in the app knows both machines are yours.

How Claude and Codex do it

Reverse engineered from the installed apps on this Mac (Claude Code 2.1.302, Claude Desktop 4.23118, Codex 26.1103), plus public docs.

Claude Code

server is the truth
  • Routines (/schedule) live on Anthropic's server (/v1/code/triggers) and run in the cloud. The Mac may sleep.
  • Local cron (/loop, durable tasks) sits in .claude/scheduled_tasks.json, is git-excluded, and runs only while a session is open. A copied file is ignored.
  • Settings and memory are local files; only .claude/ in the repo travels, by Git.

Claude Desktop

local, moving to cloud
  • Projects (knowledge, instructions) live on the server; the app keeps a read-only cache.
  • Local scheduled tasks: scheduled-tasks.json plus one SKILL.md each. They run on a 60-second tick while the app is open and awake, and never sync.
  • A migration moves them to cloud tasks, which show on every device.

Codex

runs where it was made
  • Routines are ~/.codex/automations/<id>/automation.toml, mirrored into a local database, and run in the app on that Mac.
  • An optional account mirror (gated, off here) shows them on every device, but only the installation that owns a routine runs it.
  • An owner check refuses another installation.

Claude needs its own servers to run your routines. Codex keeps execution on one machine and only mirrors the definition. That second shape is the one SpecWithCode can do without hosting anything, because our machines already talk to each other directly.

Proposed flow

  • Yours means yours. Pairing records whether the other machine is your own or a teammate's. Between your own machines, routine management is on, and routines you made by hand count as yours.
  • One definition everywhere. Each edit is signed by the machine that made it and sent to your other machines. The newer revision wins and the losing one is kept as a conflict copy. A copied database row or an unsigned copy never runs.
  • One runner. Exactly one machine holds the runner lease; only it fires. That replaces today's copy-and-delete moves.
  • Runner offline. Other machines show "Runner offline: M4" with one-click Run here.

Git stays the way code moves between machines. It is a poor fit for routines: run state changes every few minutes, many routines have no repository at all, and Claude Code itself keeps its schedule file out of Git.

Umbrella project: required?

No. SpecWithCode detects four layouts: single repo, umbrella, nested and plain folder (project.ts:319).
