Make this reusable?Inside Skills · opt-in

You’ve asked for this release-update format in three conversations on different days.

In the app: show the exact supporting messages and let the user remove any example.

Detect reusable intent plus repeated constraints, not just repeated words. Ignore retries, quoted material, assistant text and excluded conversations. Check for an existing skill first.

Proposed starting limits: three conversations across two days; one new suggestion per project per week; a 30-day candidate window. These are hypotheses to test. No interruption while typing. No background cloud analysis without opt-in.

What to reuse, what to simplify

Skill Studio already has

AI/manual authoring, provider and model selection, editable drafts, standalone/plugin placement, publish/account choices and a submission queue.

Keep its contracts and validation. Hide engine, layout and plugin controls from the simple path.

SpecWithCode already has

Composer discovery and Rescan; Settings inventory, scopes and version controls; previewed writes and exact-version readback.

Add creation without redesigning the counts and filters owned by the other worker.

“A few seconds” is a goal, not verified behavior.
There is no fresh latency measurement. Older private publication evidence was within two minutes. Show queued/checking/published and let the user continue working.
Failures should be recoverable in place
  • Generation fails: preserve the text and model selection; allow retry or manual edit.
  • Push succeeds, submission fails: report those separately and retry only the missing step.
  • Review rejects: show findings and edit a new draft. Approval alone does not mean published.
  • Install fails or an agent has stale discovery: keep the published version and retry application. Never claim it is ready early.
  • Remote state changes after preview: refresh the diff before applying. Never overwrite silently.

Standalone first. Plugins when needed.

A skill does not need to be a plugin because a model generated it. Use a plugin when hooks, tools or a coordinated bundle justify one.

A plugin release can carry a changed skill. But the inspected vskill updater skips user-level plugin bundles and directs users to reinstall the plugin. SpecWithCode’s skill-version action is not proof of a universal plugin updater. A bundle update must show all affected skills and verify the provider loaded the new bundle.
