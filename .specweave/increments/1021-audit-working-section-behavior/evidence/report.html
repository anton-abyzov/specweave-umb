The setting promises more than it controls.

On desktop/web, the Working shelf is implemented. It folds active and monitoring threads, then promotes observed returns. But the default Projects/Chats sidebar and project Threads pane ignore this switch.

The strongest fix is small: make the setting's scope explicit, then share one “needs you” predicate. Stalled runs, sign-in requests and reported blockers with monitors can currently stay folded.

Three separate mechanisms

Working is presentation. PR watches, workflows and subagents can hold completion; a dev server left behind cannot. Future scheduled jobs are outside this roster. The 6:26 AM EDT release schedule remains enabled.

Unread compares completion with the last visit; it does not decide shelf placement. Reading does not cancel a watch. Conversation scrolling follows reader intent separately.

Auto-settle is server policy. It needs all relevant PRs merged with passing checks and approved review observations, coherent timestamps and no live work or user blocker. Inactivity alone does not complete work. Host observations do not prove exact-head QA, deployment or installed acceptance.
