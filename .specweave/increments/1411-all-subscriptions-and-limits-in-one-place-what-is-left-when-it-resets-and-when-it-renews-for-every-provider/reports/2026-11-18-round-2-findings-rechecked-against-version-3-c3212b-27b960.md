## 1411: new findings

### Must-fix

**R1. AC-01's "default is what it is today" contradicts Approach 1, and the row still has no name.** AC-01 says without the option "the result is what it is today, pinned by a test"; Approach 1 says the function "returns the instance and machine ids with each account" with no "only under the option". The result is pinned today by an exact-object expectation (`packages/shared/src/usageLimits.test.ts:1029-1039`) which two new fields break, and that test file is not in T-01. Separately, `UnreportedLimitAccount` has no name field (`usageLimits.ts:446-455`), while the table says `Usage not reported by <name>` and AC-01 links "from the driver and name it has". For ACP instances the driver is the single slug `acpRegistry` (`AcpRegistryDriver.ts:90`), so without display name every ACP row (Problem 1's own list) is indistinguishable, and Copilot's link, resolving from agent id or label (`providerUsageLinks.ts:52-58`), cannot resolve. Smallest fix: say the board option also returns `environmentId`, `instanceId` and `displayName`, with the default field-for-field today's (or drop that claim, update the pinned expectation, and add `usageLimits.test.ts` to T-01); name `<name>` as that display name.

**R2. The table's "already a reading row: no second row" is false in two reachable cases.** The cited de-duplication (`usageLimits.ts:478-481`) skips a pooled account only when a key exists and the reason is not `unsupported`. Case 1: Cursor with reader off on machine B publishes `unsupported` with message and email, so the key matches the pooled row from machine A and the exception still pushes a second row, which AC-03 counts as another subscription. Case 2: Copilot's key is null (`usageLimits.ts:139-149`), so an unread instance of an already-rowed account can never be de-duplicated. Smallest fix: under the board option, a pooled-key match suppresses the row whatever the reason (default keeps today's exception), and carve keyless accounts out of the "no second row" cell or de-duplicate by driver and login; pin both in T-01.

**R3. AC-03's "at a limit" contradicts Copilot's explicit "still runs", and "account window"/"spent window" are not computable as written.** Copilot stamps `ordinaryUsageAllowed: true` exactly when premium is fully used, because spent premium does not stop it (`copilotUsageLimits.ts:195-199`); AC-03's second clause ("or an account window is fully used") overrides that stamp, so the header reports the owner's example at a limit while it runs. `spendControlReached` sits beside `ordinaryUsageAllowed` in the contract (`providerUsageLimits.ts:80-82`, set independently at `codexUsageLimits.ts:251-252`) and AC-03 never says whether it counts. "Account window" is defined only in AC-02; AC-03 does not inherit the scoped/"Overall" exclusions or say a spent window must be live (`subscriptionRows.ts:105-108`, `usageWindows.ts:49-56`), so a stale offline spent window counts forever and its past reset becomes "next reset". Smallest fix: one formula in AC-03 — `ordinaryUsageAllowed === false` or `spendControlReached === true`, or (a live, unscoped, non-"Overall" window at 100% and `ordinaryUsageAllowed !== true`); "spent window" is that same kind; past resets never show.

**R4. AC-07 does not say where "all three or none" is enforced, and the wrong place loses the percent.** Windows cross the wire in `ForwardCompatibleArray`, which drops any element its schema rejects on decode and encode (`baseSchemas.ts:128-137`). As schema checks on `ServerProviderUsageWindow` (`providerUsageLimits.ts:20-32`), one bad triple deletes the whole window; as reader-only promises, a partial triple reaches the row unspecified. Copilot can produce the bad case: `remaining` is optional/nullable (`copilotUsageLimits.ts:67-75`) while the percent can come from `percent_remaining` alone (`:113-125`), and AC-07 omits amounts only "when the quota is unlimited or has no entitlement". Smallest fix: pin individually-optional schema fields with no cross-field check, reader emits all-or-none (none also when `remaining` is absent or non-finite), row treats a partial/invalid triple as no amounts; or enforce in the schema and accept the dropped window — say which.
