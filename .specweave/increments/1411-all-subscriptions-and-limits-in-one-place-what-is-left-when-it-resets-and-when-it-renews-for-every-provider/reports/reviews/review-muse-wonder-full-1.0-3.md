## 1411: new findings

### Must-fix

**R1. AC-01's "default is what it is today" contradicts Approach 1, and the row still has no name.**

What is wrong: AC-01 says without the new option "the result is what it is today, pinned by a test". Approach 1 says the function "returns the instance and machine ids with each account", with no "only under the option". The result is pinned today by an exact-object expectation (`packages/shared/src/usageLimits.test.ts:1029-1039`), which two new fields break, and that test file is not in T-01's Files (T-01 puts new tests in a new file because the old one is 1,558 lines). Separately, `UnreportedLimitAccount` has no name field (`packages/shared/src/usageLimits.ts:446-455`: key, driver, environmentLabel, offline, email, plan, reason, message), while the table's first row says `Usage not reported by <name>` and AC-01 links "from the driver and name it has". For ACP instances the driver is the single slug `acpRegistry` (`apps/server/src/provider/Drivers/AcpRegistryDriver.ts:90`), so without the instance's display name every ACP row (Copilot, Devin, Pi, Antigravity: the instances Problem 1 names) is indistinguishable, and Copilot's link, which resolves from the agent id or label (`packages/shared/src/providerUsageLinks.ts:52-58`), cannot resolve. The board could look the provider up again from the returned ids, but no AC or Approach step says it does.

Smallest fix: say the board option also returns `environmentId`, `instanceId` and `displayName`, and that the default result is field-for-field today's (or drop that claim, update the pinned expectation, and add `usageLimits.test.ts` to T-01). Name `<name>` as that display name, falling back to the driver label.

**R2. The table's "already a reading row: no second row" is false in two reachable cases.**

What is wrong: the de-duplication the table cites (`packages/shared/src/usageLimits.ts:478-481`) skips a pooled account only when an account key exists and the reading's reason is not `unsupported`. Case one: Cursor with its reader off on machine B publishes `unsupported` with a message and keeps its email, so the key matches the pooled row from machine A and the exception still pushes a second row, which AC-03 then counts as another subscription. Case two: Copilot's key is null (no email, no fingerprint, `usageLimits.ts:139-149`), so an unread Copilot instance of an account that already has a reading row can never be de-duplicated. The widening the spec proposes does not change either line.

Smallest fix: state that under the board option a pooled-key match suppresses the row whatever the reason (the default keeps today's exception for the pooled view's Console-billing case), and carve keyless accounts out of the "no second row" cell in the table, or de-duplicate them by driver and login. Pin both cases in the T-01 tests.

**R3. AC-03's "at a limit" contradicts Copilot's explicit "still runs", and "account window" / "spent window" are not computable as written.**

What is wrong: Copilot's reader stamps `ordinaryUsageAllowed: true` exactly when the premium window is fully used, because spent premium requests do not stop Copilot (`apps/server/src/provider/copilotUsageLimits.ts:195-199`). AC-03 defines at-limit as "ordinary use is not allowed, or an account window is fully used", so the second clause overrides that stamp and the header reports the owner's own example as at a limit while it runs. The contract also carries `spendControlReached` beside `ordinaryUsageAllowed` (`packages/contracts/src/providerUsageLimits.ts:80-82`; Codex sets them independently, `apps/server/src/provider/codexUsageLimits.ts:251-252`), and AC-03 never says whether it counts. "Account window" is defined only in AC-02, for notes; AC-03 does not say it inherits the model-scoped and Cursor "Overall" exclusions, nor that a spent window must be live (a window whose reset has passed is dropped from the row, `subscriptionRows.ts:105-108`, via `isLiveWindow`, `packages/shared/src/usageWindows.ts:49-56`): computed from the raw reading, a stale offline spent window counts forever and its past reset becomes the header's "next reset".

Smallest fix: one formula in AC-03: at-limit is `ordinaryUsageAllowed === false` or `spendControlReached === true`, or (a live, unscoped, non-"Overall" window at 100% and `ordinaryUsageAllowed !== true`); "spent window" is that same window kind; resets at or before now never appear in the header.

**R4. AC-07 does not say where "all three or none" is enforced, and the wrong place loses the percent.**

What is wrong: windows cross the wire in a `ForwardCompatibleArray`, which drops any element its schema rejects, on decode and on encode (`packages/contracts/src/baseSchemas.ts:128-137`). If finite-and-non-negative, the 1-to-24-character unit and all-or-none are schema checks on `ServerProviderUsageWindow` (`packages/contracts/src/providerUsageLimits.ts:20-32`), one bad triple deletes the whole window, percent included; if they are reader-only promises, a partial triple from another machine's newer build reaches the row unspecified. Copilot's own data can produce the bad case: `remaining` is optional and nullable (`copilotUsageLimits.ts:67-75`) while the percent can come from `percent_remaining` alone (`:113-125`), and AC-07's Copilot sentence says amounts are absent only "when the quota is unlimited or has no entitlement", not when `remaining` is missing or non-finite.

Smallest fix: pin that the schema fields are individually optional with no cross-field check, the publishing reader emits all three or none (none also when `remaining` is absent or non-finite), and the row treats a partial or invalid triple as no amounts; add that case to the T-04 tests. Or enforce in the schema and accept the dropped window: say which.

## 1415: findings

### Must-fix

**P1. Cursor has a second token reader, and no AC gates it.**

What is wrong: AC-02 promises that with its switch off a reader "opens no file and no Keychain item", and the table says Cursor off means "No Keychain and no `auth.json` read, on any platform". The account-history scan reads the same token on a second path: `UsageService` returns early only for macOS Keychain with the switch off (`apps/server/src/usage/UsageService.ts:752-767`), and otherwise calls `readCursorAccountUsage` with the `auth.json` path on Windows, Linux and macOS-file (`:776-784`), which reads and parses the file (`apps/server/src/usage/cursorUsageReader.ts:69-96`). Gating `cursorUsageLimits.ts` alone therefore leaves the file read in place exactly on the platforms D-04 says go off. `UsageService.ts` is listed in T-02's Files but no AC says what changes there; the existing switch is already described to the person as covering "account history and plan limits" (`apps/web/src/components/settings/UsageProviderSettings.tsx:152`), while AC-05's new sentence mentions only asking Cursor for usage, and the scan key already invalidates on this flag (`UsageService.ts:1001`). The Usage page and phone "enable" prompts also hang off this scan's `enableCursorKeychain` action (`:758-766`).

Smallest fix: add one AC (or one clause to AC-02) that the history scan takes the same early return on every platform when the switch is off and no environment token is set, keeping its message and action; make AC-05's Cursor sentence cover history, or scope history explicitly Out with the reason.

**P2. AC-08's screenshots are required and untasked.**

What is wrong: AC-08 requires "headless screenshots of the three switches and of a row that is off". T-04, which owns AC-07 and AC-08, lists one file (the acceptance report) and the test `specweave verify 1415-...`: no fixture, no screenshot command, no output paths. This is the exact defect round 2's N10 fixed in 1411, reintroduced in the split.

Smallest fix: name the fixture or settings test harness that renders the switches and an off row, its files, and the command, as 1411 T-06 now does.

**P3. H1 is an open fork that changes three ACs, and the code already answers it.**

What is wrong: H1 leaves open whether anything besides the email depends on Grok's read, and says if it does, "the switch gates only the usage call and the email read stays, and the sentence in AC-05 changes", contradicting AC-02, AC-04 and D-03 as written. At `c46e2efe5` the answer is checkable: Grok's sign-in state and model list come from the CLI's own commands (`grok --version`, `grok models`, `apps/server/src/provider/GrokProvider.ts:403`, `:469-470`), and `readGrokAccount` is called from one place, only to add the email and the usage limits to an already-authenticated snapshot (`apps/server/src/provider/Drivers/GrokDriver.ts:149-157`). What the email does feed is identity: the account key (`packages/shared/src/usageLimits.ts:139-149`) and the server's subscription-change memory, which falls back to the email when there is no subscription key (`apps/server/src/provider/subscriptionIdentity.ts:59-66`). A spec a builder can follow either way is not ready.

Smallest fix: close H1 in the spec on this evidence: the switch gates the whole `readGrokAccount`; sign-in and models are unaffected; while off, account-change detection for Grok has no identity to compare, which is accepted and stated.

### Should-fix

**P4. The off message's precedence over older `unsupported` causes is unpinned.** Each reader already returns `unsupported` for reasons that are not the switch: OpenCode on an external server or disabled, and its unmetered no-Go-plan case (`openCodeUsageLimits.ts:39-46`); Cursor with only `CURSOR_API_KEY` set (`cursorUsageLimits.ts:151-152`); Grok with `XAI_API_KEY` set or an `api_key` auth mode (`grokUsageLimits.ts:77`, `:133`, `:155-156`). If the switch check runs first, those rows say "Usage reading is off" and offer "Show it here", and turning the switch on lands on the same unsupported reading; if it runs last, a genuinely off reader can be masked by an incidental env key. Smallest fix: one precedence sentence per reader (suggested: the pre-existing structural causes win, the switch next, token sources last), with the table's cells read subject to it. The rest of the per-reader table checks out against the code, including OpenCode's stored-key-over-environment rule (`openCodeUsageLimits.ts:55-68`) and both first-choice env tokens (`cursorUsageLimits.ts:149`, `grokUsageLimits.ts:120-121`).

**P5. AC-04 is unconditional where the table is not, and silent about resets missed while off.** With a vendor token in the environment the reader still runs and identity is still published: Grok's email comes out of the `GROK_AUTH` content (`grokUsageLimits.ts:120-153`) and OpenCode Go's fingerprint is computed from the `OPENCODE_AUTH_CONTENT` key (`openCodeUsageLimits.ts:106-116`), so "Grok's row then has no email" holds only for the no-token cell. Grok's env path also reads its config files before the credential (`grokUsageLimits.ts:102-119`), which AC-02's "opens no file" should scope to the credential file or name. And while a reader is off, resets that happen are never observed, so the reset ledger and limit history keep what they stored but gain a permanent gap; AC-04's "reset history ... show[s] again" should say it is not backfilled. Smallest fix: scope AC-04's first sentences to the switch-off-no-token case and add the no-backfill sentence.

**P6. The way from the row to the switch is missing a file and a target.** "Show it here" renders on the no-reading row, which after 1411 is `NoReadingRow.tsx`; T-03 lists `SubscriptionsView.tsx` but not that component, so the callback has nowhere to land. Smallest fix: add `NoReadingRow.tsx` (and its test) to T-03 and name those two search changes.

**P7. D-04 is broader than its wording and is still only defaulted.** D-04 says the owner was not told Cursor on Windows and Linux goes off on update; the same is true of a Mac whose Cursor CLI keeps its login in a file (`AGENT_CLI_CREDENTIAL_STORE=file` takes the file branch, `cursorUsageLimits.ts:162-194`), and of the account history on all three (P1). AC-07's release-notes sentence should cover all of them, and a defaulted switch-off of a working read for existing users belongs in Asked before sw-do, next to D-01's "he was told Grok and OpenCode Go go off".

Grouped minor points.
